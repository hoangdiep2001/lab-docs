0. Quy tắc loại trừ nhanh (gặp là loại)

  • Secret/credential nằm trong code, repo Git, user data, file đóng gói cùng app, base64.
  • Chia sẻ access key, IAM user cho end-user hay cho ứng dụng chạy trên AWS (thay vào đó dùng role).
  • Bucket policy principal "*" khi đề hỏi "most secure".
  • Viết Lambda / EC2 / cron chạy định kỳ 15 phút khi đề yêu cầu "immediately" (thay vào đó dùng event).
  • Lambda gắn EBS, mount S3, chọn instance type cho Lambda: không tồn tại.
  • "Global certificate", "deletions inventory", "TranslateText caching": tính năng bịa.
  • Sticky session khi đề yêu cầu chịu lỗi (fault tolerant).
  • Least effort / operational overhead → ưu tiên tính năng có sẵn (managed) hơn tự viết code.

1. Lambda

Dấu hiệu Đáp án
Chạy chậm, CPU-bound Tăng memory (CPU tăng theo)
Thư viện lớn, giảm package Layer (giải nén ≤ 250 MB)
File dùng chung, append, team khác cập nhật, on-prem truy cập EFS mount vào Lambda (cần VPC)
Cache tạm giữa các lần gọi /tmp (riêng từng môi trường thực thi)
"too many connections" tới RDS RDS Proxy + kết nối khởi tạo ngoài handler
Ai được gọi Lambda Resource-based policy (add-permission, vd. cho ALB khi đăng ký bằng CLI)
Lambda được làm gì Execution role
Chia traffic giữa các version Version + weighted alias. Chuyển dần → CodeDeploy canary/linear
Async lỗi DLQ (chỉ SQS standard / SNS, không FIFO, không Kinesis) hoặc Destinations. Cần quyền trong execution role
Đặt trần concurrency, bảo vệ API/DB phía sau Reserved concurrency (+ SQS làm buffer)
Chống cold start Provisioned concurrency (không phải trần)
Chạy định kỳ EventBridge schedule
Lưu tạm trong lúc chạy /tmp (512 MB, tăng được đến 10 GB)
Truy cập RDS trong private subnet Gắn Lambda vào VPC + security group
Nguồn SQS / Kinesis / DynamoDB Streams Event source mapping (giới hạn được max concurrency)
Kinesis bị trễ (IteratorAge tăng) Thêm shard, tăng memory, tăng ParallelizationFactor
Cấu hình động từ AppConfig AppConfig Agent Lambda extension (localhost:2772)
Biến môi trường nhạy cảm Encryption helpers (mã hóa in transit bằng KMS)

3. DynamoDB

Dấu hiệu Đáp án
"single-digit millisecond" DynamoDB. "microsecond" → DAX
Lấy nhiều item theo key, kể cả từ nhiều bảng BatchGetItem
Query theo thuộc tính không phải key GSI (thêm sau được, có capacity riêng)
LSI Cùng PK với bảng, chỉ tạo lúc tạo bảng, dùng chung capacity
Tìm theo tiền tố begins_with chỉ dùng trên sort key
Sắp xếp giảm dần ScanIndexForward = false
Throttle dù chưa vượt capacity Hot partition → chọn PK có cardinality cao (username, ID)
Item lớn hơn 400 KB, ảnh, file Lưu S3, DynamoDB giữ object key
Scan Gần như luôn sai nếu có cách dùng Query/GSI
Tự xóa dữ liệu cũ, job xóa làm throttle TTL (xóa nền, không tốn WCU)
"Top N theo nhóm" GSI: PK = nhóm, SK = điểm, ScanIndexForward=false + Limit
Cập nhật nhiều item, lỗi thì rollback TransactWriteItems (hoặc transaction trên RDS/Aurora)
Request trùng (idempotency) Lưu request ID vào DynamoDB, kiểm tra trước khi xử lý
Mã hóa mặc định AWS owned key (không tạo được, không có ARN)

4. Cache & session

  • Real-time / luôn mới → write-through. Chấp nhận dữ liệu cũ, tiết kiệm → lazy loading.
  • Redis: persistence, replication, sorted set (sort/rank), mã hóa at rest. Memcached: đa luồng, đơn giản, không persistence.
  • Session chịu lỗi → ElastiCache hoặc DynamoDB (không dùng sticky session).
  • RDS đọc nhiều → read replica (standby của Multi-AZ không phục vụ đọc, chỉ để failover).

6. IAM & truy cập

  • EC2/ECS/Lambda gọi AWS → IAM role (instance profile / task role / execution role). Sửa policy có hiệu lực ngay.
  • Credential provider chain: biến môi trường → file ~/.aws/credentials → instance profile. Cái nào có trước thì dùng cái đó. File chứa key admin thì role (kể cả explicit deny) bị bỏ qua.
  • Instance profile chỉ chứa role (không chứa user/group). Least privilege, không cấp admin.
  • Truy cập tạm vào account khác → cross-account role + sts:AssumeRole.
  • SSO đang chạy bỗng Access Denied → credential hết hạn → aws sso login.
  • Cross-account S3 → quyền IAM bên gọi và bucket policy liệt kê đúng account ID.
  • Cognito + S3 mỗi user một folder → IAM policy với biến ${cognito-identity.amazonaws.com:sub}.
  • Nhiều account, nhiều dev → IAM Identity Center (permission set).
  • IAM DB authentication chỉ cho MySQL / PostgreSQL (không có SQL Server).

8. CI/CD & triển khai

  • Nguồn kích hoạt CodePipeline theo event: CodeCommit, S3 (cùng GitHub, ECR). Package .jar/npm mới → CodeArtifact + EventBridge.
  • CodeBuild: unit test → stage mới sau Source, input = source artifact. Test report → reports: trong buildspec. Build chậm vì dependency → local cache + cache.paths.
  • Amplify Hosting E2E test → phase test trong amplify.yml.
  • Git: freeze release → release branch, fix trên đó, sau release merge về main (không rebase main).
  • CodeDeploy: appspec.yml (không phải của CodeBuild). Canary / linear / all-at-once.
  • Elastic Beanstalk: deploy mà không cần biết hạ tầng (PaaS).
  • IaC + version + rollback → CloudFormation (+ CodeCommit).
  • Test thay đổi mà không đụng môi trường người khác → deploy vào account/stack riêng.

9. Container

  • Ít công vận hành nhất → image trên ECR + ECS trên Fargate (EKS phức tạp hơn).
  • Biến môi trường, secret cho container → task definition (environment, secrets).
  • EC2 → Fargate: PutClusterCapacityProviders (FARGATE làm base, FARGATE_SPOT bổ sung). CreateCapacityProvider chỉ dùng cho ASG.
  • Dọn image cũ → ECR lifecycle policy. Chống ghi đè tag → tag immutability. Deploy đúng image đã test → tag theo commit SHA / digest (không dùng latest).
  • Pull image ECR, ghi awslogs, lấy secret → task execution role. Code trong container gọi AWS → task role.
  • Rolling update không giảm capacity → minimumHealthyPercent=100, maximumPercent=200. Tự rollback → deployment circuit breaker.
  • EKS: chưa sẵn sàng thì không nhận traffic → readiness probe. Treo thì restart → liveness probe.

10. Event & messaging

  • Một event → nhiều consumer độc lập → SNS fan-out (một message SQS chỉ một consumer xử lý).
  • Lọc message SNS → subscription filter policy.
  • Phản ứng ngay với API call → EventBridge rule trên event CloudTrail.
  • S3 upload kích hoạt Lambda → S3 event notification hoặc EventBridge rule + target Lambda.
  • SQS FIFO: dedup trong 5 phút, có message group ID. Cần đúng thứ tự + không trùng → FIFO.
  • Fan-out mà vẫn giữ thứ tự → SNS FIFO → SQS FIFO.
  • Vừa gửi email vừa kích hoạt Lambda → SNS (SQS không gửi email).
  • Xử lý trùng với SQS standard → do at-least-once + visibility timeout ≤ timeout của Lambda (nên ≥ 6 lần).
  • Lambda lỗi khi đọc SQS → DLQ qua redrive policy của queue (maxReceiveCount).
  • Message tối đa 256 KB.

12. S3 & CloudFront

  • Xóa object sau N ngày → Lifecycle rule (không viết code).
  • Link tải tạm thời, chỉ cho subscriber trả phí, chia sẻ cho người ngoài → pre-signed URL (tối đa 7 ngày).
  • Có versioning muốn xóa hẳn → Lifecycle: expire current và permanently delete noncurrent version.
  • Request rate cao → phân tán key qua nhiều prefix (3.500 PUT / 5.500 GET mỗi giây mỗi prefix).
  • Một bản gốc, trả về khác nhau tùy người đọc (bỏ PII) → S3 Object Lambda access point.
  • Trình duyệt chặn JS/font từ bucket khác → CORS trên bucket chứa tài nguyên.
  • Resize ảnh theo thiết bị, tiết kiệm → Lambda@Edge xử lý khi có request + lưu kết quả vào S3.
  • Web không cập nhật qua CloudFront → invalidation. Chậm toàn cầu → CloudFront trước ALB.
  • Mã hóa đầu-cuối qua CloudFront → Viewer Redirect HTTP→HTTPS + Origin Match Viewer / HTTPS Only.

13. Khác

  • Tạo EC2 mới → run-instances. Bật lại instance đã stop → start-instances.
  • Evidently: ép một user vào một variation → override theo user ID.
  • IP client thật sau ALB → header X-Forwarded-For.
  • Xác thực OIDC/Cognito mà không sửa app → ALB + listener HTTPS 443 + action authenticate-oidc (NLB không làm được).
