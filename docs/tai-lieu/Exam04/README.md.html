Câu 1

Question: A developer is building an order-intake API with Amazon API Gateway and AWS Lambda. The Lambda function calls an inventory service, a payment service, and an email service synchronously before it returns a response. During peak hours, responses take more than 20 seconds, and a failure in the email service causes the entire request to fail. Customers need only a confirmation that the order was received. Which solution will meet these requirements with the LEAST latency for customers?
- A. Increase the Lambda function timeout to 15 minutes and increase the API Gateway integration timeout.
- B. Enable API Gateway caching for the order-intake method.
- C. Configure the Lambda function to write the order to an Amazon SQS queue and return an HTTP 202 response. Process the orders from the queue by using a separate Lambda function.
- D. Configure provisioned concurrency for the Lambda function.

Xem đáp án **Đáp án: C** · *Domain 1.1 – sync vs async* - ✅ C: tách rời (decouple): API chỉ ghi vào SQS rồi trả 202 ngay. Xử lý phía sau chạy bất đồng bộ, service email lỗi thì message vẫn nằm trong queue để retry, không làm hỏng request của khách. - ❌ A: vẫn đồng bộ, khách vẫn phải chờ. Ngoài ra timeout tích hợp mặc định của API Gateway là 29 giây. - ❌ B: không cache request POST tạo đơn hàng. - ❌ D: provisioned concurrency chỉ giảm cold start, không giảm thời gian gọi 3 service.

Câu 2

Question: An application uses the AWS SDK for Python (Boto3) to write items to an Amazon DynamoDB table that uses provisioned capacity. During short traffic bursts, some writes fail with a ProvisionedThroughputExceededException error. The developer wants the application to handle these errors gracefully with the LEAST amount of custom code. What should the developer do?
- A. Configure the SDK retry mode to standard or adaptive, and increase the maximum number of attempts so that requests are retried with exponential backoff and jitter.
- B. Wrap each PutItem call in a loop that retries the call immediately until it succeeds.
- C. Change all reads in the application to strongly consistent reads.
- D. Add a global secondary index (GSI) to the table to spread the write load.

Xem đáp án **Đáp án: A** · *Domain 1.1 – fault tolerance* - ✅ A: SDK có sẵn cơ chế retry **exponential backoff + jitter**, chỉ cần cấu hình (`retries={'mode': 'adaptive', 'max_attempts': 10}`). Chế độ adaptive còn tự hạ tốc độ gửi phía client. - ❌ B: retry ngay lập tức làm bão request nặng hơn. - ❌ C: liên quan đến đọc, trong khi lỗi xảy ra khi ghi. - ❌ D: GSI còn tiêu tốn thêm WCU khi ghi.

Câu 3

Question: A company exposes a REST API by using Amazon API Gateway. The backend AWS Lambda function spends compute time rejecting requests that are missing required fields in the JSON body. The developer wants to reject malformed requests before the Lambda function is invoked, without writing additional code. What should the developer do?
- A. Add a Lambda authorizer that parses the request body and denies malformed requests.
- B. Associate an AWS WAF web ACL that has a rate-based rule with the API stage.
- C. Configure a mapping template that converts the request body to XML.
- D. Create a model that defines a JSON schema for the request body, and enable a request validator on the method.

Xem đáp án **Đáp án: D** · *Domain 1.1 – API validation* - ✅ D: **model (JSON Schema) + request validator** cho phép API Gateway tự trả **400** khi body sai, Lambda không bị gọi. - ❌ A: phải viết code. Hơn nữa authorizer dùng để xác thực, không kiểm tra body. - ❌ B: rate-based rule dùng để chống flood, không kiểm tra schema. - ❌ C: mapping template biến đổi dữ liệu, không validate.

Câu 4

Question: A company collects clickstream events from its website. The events must be stored in Amazon S3 in Apache Parquet format so that analysts can query the data by using Amazon Athena. A delay of a few minutes is acceptable. The developer wants to avoid building and managing consumer applications. Which solution will meet these requirements?
- A. Send the events to Amazon Data Firehose. Enable record format conversion to Apache Parquet, and configure Amazon S3 as the destination.
- B. Send the events to Amazon Kinesis Data Streams. Write a consumer application on Amazon EC2 that converts the records to Parquet and writes them to Amazon S3.
- C. Send the events to an Amazon SQS queue. Configure a Lambda function to write each message to Amazon S3 as a separate object.
- D. Write the events to an Amazon DynamoDB table. Export the table to Amazon S3 every minute.

Xem đáp án **Đáp án: A** · *Domain 1.1 – streaming data* - ✅ A: **Data Firehose** là dịch vụ managed, không cần viết consumer. Firehose gom dữ liệu theo buffer (kích thước/thời gian, gần real-time), **chuyển định dạng sang Parquet/ORC** (dùng schema từ Glue) và có thể biến đổi qua Lambda trước khi ghi vào S3. - ❌ B: phải tự viết và vận hành consumer. - ❌ C: mỗi message thành một object nhỏ, không phải Parquet, Athena đọc chậm. - ❌ D: vòng vèo, không phù hợp với clickstream.

Câu 5

Question: An IoT application writes sensor readings to an Amazon Kinesis data stream that has 10 shards. The developer uses the device type as the partition key. There are only three device types. Amazon CloudWatch shows WriteProvisionedThroughputExceeded errors on a few shards while the other shards are almost idle. Readings from the same device must be processed in order. What should the developer do?
- A. Increase the number of shards in the stream to 50.
- B. Use a random UUID as the partition key for every record.
- C. Use the device ID as the partition key.
- D. Switch the stream to on-demand capacity mode.

Xem đáp án **Đáp án: C** · *Domain 1.1 – streaming / partition key* - ✅ C: device ID có **cardinality cao** nên dữ liệu rải đều trên các shard. Kinesis giữ thứ tự **trong cùng partition key**, nên mỗi device vẫn được xử lý đúng thứ tự. - ❌ A, D: chỉ có 3 giá trị key thì tối đa 3 shard "nóng", thêm shard hay đổi sang on-demand cũng không giải quyết. - ❌ B: UUID ngẫu nhiên phá vỡ thứ tự theo device.

Câu 6

Question: An Amazon SQS queue is subscribed to an Amazon SNS topic. Raw message delivery is not enabled. A publisher sends a JSON object to the topic. An AWS Lambda function processes messages from the queue. The function code calls json.loads(record["body"]) and then reads the orderId field, but the field is always missing. What is the cause of this issue?
- A. Amazon SQS encodes all message bodies in Base64.
- B. The batch size of the Lambda event source mapping is greater than 1.
- C. Amazon SNS removes JSON attributes from messages before delivery.
- D. The SQS message body contains an SNS envelope. The original payload is a JSON string in the Message field and must be deserialized again.

Xem đáp án **Đáp án: D** · *Domain 1.1 – serialize/deserialize* - ✅ D: SNS bọc payload trong một "envelope" (`Type`, `MessageId`, `Message`, …). Phải parse 2 lần: `json.loads(json.loads(body)["Message"])`. Cách khác là bật **raw message delivery** trên subscription. - ❌ A: SQS không tự mã hóa Base64. - ❌ B: batch size không làm thay đổi nội dung body. - ❌ C: SNS không sửa nội dung payload.

Câu 7

Question: When a new object is uploaded to an Amazon S3 bucket, three independent teams must react to the event. One team runs an AWS Lambda function. One team needs the event in an Amazon SQS queue. One team wants to filter events by object size and send them to an AWS Step Functions state machine. The developer wants to add new consumers in the future without changing the bucket's notification configuration. What should the developer do?
- A. Configure three S3 event notifications on the bucket, one for each destination.
- B. Enable Amazon EventBridge notifications on the bucket. Create an EventBridge rule for each consumer.
- C. Configure S3 replication to three separate buckets, one for each team.
- D. Schedule a Lambda function to list new objects every minute and dispatch them to each team.

Xem đáp án **Đáp án: B** · *Domain 1.1 – event-driven* - ✅ B: bật EventBridge trên bucket một lần, sau đó thêm bao nhiêu **rule** cũng được. EventBridge **lọc theo nội dung** (như object size), hỗ trợ đích Step Functions, và có archive/replay. - ❌ A: S3 notification không cho 2 cấu hình **trùng prefix/suffix cho cùng loại event**, không lọc được theo size, và mỗi lần thêm consumer phải sửa bucket. - ❌ C: tốn chi phí, vẫn không giải quyết việc phát sự kiện. - ❌ D: polling, chậm.

Câu 8

Question: A development team uses Kiro to build a new microservice. The team lead wants the AI agent to produce a requirements document, a technical design, and a list of discrete implementation tasks that developers can review and approve before any code is generated. Which Kiro feature should the team use?
- A. Specs (spec-driven development)
- B. Agent hooks

Câu 9

Question: A team uses Kiro in its repository. The team wants the AI agent to always follow the company's coding standards, use a specific logging library, and follow the team's naming conventions in every session, without repeating these instructions in each prompt. What should the team do?
- A. Create an agent hook that runs every time a file is saved.
- B. Add the instructions as comments at the top of every source file.
- C. Add steering files (Markdown) to the .kiro/steering directory of the repository.
- D. Create a new spec for each feature that repeats the standards.

Xem đáp án **Đáp án: C** · *Domain 1.1 – AI-assisted development (Kiro)* - ✅ C: **steering files** (`.kiro/steering/*.md`) cung cấp ngữ cảnh lâu dài cho agent (tech stack, conventions, cấu trúc dự án), được nạp vào mọi tương tác mà không cần nhắc lại. - ❌ A: hook dùng để chạy hành động khi có sự kiện, không dùng để lưu quy ước chung. - ❌ B: rải comment khắp file, khó bảo trì. - ❌ D: lặp lại trong mỗi spec, trái với yêu cầu đề.

Câu 11 (chọn 2)

Question: An application calls the Amazon Bedrock InvokeModel API during business hours. Under heavy load, some calls fail with a ThrottlingException error. The developer must reduce the number of failed requests. Which actions should the developer take? (Choose two.)
- A. Increase the memory of the Lambda function that calls Amazon Bedrock.
- B. Implement retries with exponential backoff and jitter in the application.
- C. Create a model customization job for the model.
- D. Use a cross-Region inference profile to distribute requests across multiple AWS Regions.
- E. Enable model invocation logging.

Xem đáp án **Đáp án: B, D** · *Domain 1.1 – tích hợp AI service / resilience* - ✅ B: throttling là lỗi tạm thời, nên retry với **exponential backoff + jitter**. - ✅ D: **cross-Region inference profile** định tuyến request sang nhiều Region, tăng throughput và giảm throttling. - ❌ A: memory của Lambda không ảnh hưởng đến quota của Bedrock. - ❌ C: fine-tune không tăng quota on-demand. - ❌ E: logging chỉ để quan sát, không giảm lỗi.

Câu 12

Question: An AWS Lambda function is connected to private subnets in a VPC so that it can query an Amazon RDS database. The function also must call a third-party HTTPS API on the internet. Calls to the third-party API time out. What should the developer do to resolve the issue?
- A. Assign a public IP address to the Lambda function's elastic network interface.
- B. Create a NAT gateway in a public subnet. Update the route tables of the private subnets to send internet-bound traffic to the NAT gateway.
- C. Remove the Lambda function from the VPC.
- D. Create an interface VPC endpoint for the third-party API.

Xem đáp án **Đáp án: B** · *Domain 1.2 – Lambda trong VPC* - ✅ B: Lambda gắn VPC **không có internet**. Phải đi qua **NAT gateway** đặt ở public subnet (subnet có route ra Internet Gateway). - ❌ A: không gán được public IP cho ENI của Lambda. Kể cả gắn vào public subnet cũng không ra được internet. - ❌ C: ra khỏi VPC thì mất kết nối tới RDS trong private subnet. - ❌ D: interface endpoint dùng cho dịch vụ AWS hoặc PrivateLink service, không dùng cho API bất kỳ trên internet.

Câu 13 (chọn 2)

Question: An AWS Lambda function runs in private subnets that have no route to the internet. The function must read items from an Amazon DynamoDB table and retrieve a secret from AWS Secrets Manager. Company policy prohibits internet access from the subnets. Which actions should the developer take? (Choose two.)
- A. Create a gateway VPC endpoint for DynamoDB and associate it with the private subnets' route tables.
- B. Create a NAT gateway and route the private subnets' traffic through it.
- C. Create an interface VPC endpoint (AWS PrivateLink) for Secrets Manager in the private subnets.
- D. Create a VPC peering connection to the Secrets Manager service VPC.
- E. Create an AWS Direct Connect connection.

Powertools Metrics hỗ trợ sẵn. - ❌ A: tự xây dựng, không phải metric của CloudWatch. - ❌ B: tăng độ trễ và có thể bị throttle. - ❌ D: metadata không tạo ra metric.

Câu 58

Question: A company wants to receive an email notification when the number of concurrent AWS Lambda executions in an account reaches 80% of the account's concurrency quota. What should the developer do?
- A. Create a CloudWatch alarm on the Lambda ConcurrentExecutions metric compared to the quota by using the SERVICE_QUOTA metric math function (for example, from the Service Quotas console). Configure the alarm to publish to an Amazon SNS topic with an email subscription.
- B. Write a Lambda function that runs every minute, counts running functions, and sends an email.
- C. Use AWS CloudTrail to count Invoke API calls.
- D. Set reserved concurrency on every function to 80% of the quota.

Xem đáp án **Đáp án: A** · *Domain 4.2 – alert theo quota / sự kiện* - ✅ A: Service Quotas tích hợp với CloudWatch: tạo alarm **% sử dụng quota** bằng hàm `SERVICE_QUOTA(metric)`, sau đó gửi **SNS** đến email. Tương tự, để biết khi deploy xong: tạo **EventBridge rule** cho sự kiện CodeDeploy hoặc CodePipeline state change rồi gửi SNS. - ❌ B: tự viết cơ chế polling. - ❌ C: CloudTrail không ghi data event Invoke theo mặc định, và không phải công cụ đo concurrency. - ❌ D: giới hạn concurrency chứ không cảnh báo.

Câu 59

Question: A developer uses AWS X-Ray to trace a serverless application. The support team needs to search for all traces for a specific customer by using a filter expression in the X-Ray console. The developer currently records the customer ID as segment metadata. What should the developer do?
- A. Increase the X-Ray sampling rate to 100%.
- B. Record the customer ID as an annotation instead of metadata.
- C. Write the customer ID to CloudWatch Logs.
- D. Add the customer ID to the trace header as a new trace ID.

Câu 60 (chọn 2)

Question: An application runs on Amazon EKS. When new pods start, they take 30 seconds to load a cache, but they receive traffic immediately and return errors. Occasionally, a pod deadlocks and stops responding, but Kubernetes never restarts it. Which actions should the developer take in the pod specification? (Choose two.)
- A. Increase the number of replicas in the deployment.
- B. Configure a Horizontal Pod Autoscaler.
- C. Configure a readiness probe that succeeds only after the cache is loaded.
- D. Increase the size of the node group.
- E. Configure a liveness probe that checks an endpoint that fails when the application is deadlocked.

Xem đáp án **Đáp án: C, E** · *Domain 4.2 – health check, liveness/readiness* - ✅ C: **readiness probe**: pod chưa sẵn sàng thì không nhận traffic (bị loại khỏi Service endpoints). - ✅ E: **liveness probe**: kiểm tra thất bại thì kubelet **khởi động lại container**. (Với startup chậm có thể thêm startup probe.) Bên ECS/ALB tương đương là health check của target group và `healthCheck` trong container definition. - ❌ A, B, D: thêm số lượng pod hay node không sửa được pod lỗi.

Câu 61

Question: An AWS Lambda function connects to an Amazon Aurora MySQL database. During traffic spikes, the function scales to hundreds of concurrent executions, and the database returns "Too many connections" errors. What should the developer do to resolve the issue with the LEAST application changes?
- A. Increase the memory of the Lambda function.
- B. Open and close a new database connection inside the handler on every invocation.
- C. Configure an Amazon SQS queue between the client and the database.

Câu 62

Question: A latency-sensitive API uses an AWS Lambda function written in Java. Cold starts take up to 6 seconds because of framework initialization. Traffic is unpredictable, and the company wants to reduce cold start latency at the LOWEST cost. What should the developer do?
- A. Configure provisioned concurrency for 100 execution environments 24 hours a day.
- B. Increase the timeout of the function.
- C. Enable Lambda SnapStart on the function's published versions.
- D. Schedule an EventBridge rule to invoke the function every minute.

Xem đáp án **Đáp án: C** · *Domain 4.3 – concurrency / cold start* - ✅ C: **SnapStart** chụp snapshot của execution environment sau khi init và khôi phục từ snapshot khi cold start, nên **khởi động nhanh hơn nhiều**. Với Java không tốn thêm phí. Áp dụng trên **published version hoặc alias**. Lưu ý dữ liệu unique (random, kết nối) cần làm mới sau khi restore. - ❌ A: tốn tiền 24/7, và với traffic khó đoán thì khó chọn con số. - ❌ B: timeout không liên quan đến cold start. - ❌ D: chỉ giữ ấm 1 environment, không chịu được khi traffic tăng.

Câu 63

Question: A CPU-intensive AWS Lambda function is configured with 512 MB of memory. The developer wants a data-driven recommendation for the memory setting that balances cost and performance, based on the function's actual usage history. What should the developer use?
- A. AWS Compute Optimizer recommendations for Lambda functions (or the open-source AWS Lambda Power Tuning tool)
- B. Increase the function timeout to the maximum.
- C. Set reserved concurrency to 1.
- D. Change the function architecture from arm64 to x86_64.

Xem đáp án **Đáp án: A** · *Domain 4.3 – tối ưu memory/compute* - ✅ A: **Compute Optimizer** phân tích lịch sử sử dụng để gợi ý memory. **Lambda Power Tuning** (chạy bằng Step Functions) thử nhiều mức memory rồi vẽ biểu đồ chi phí/tốc độ. Câu 64

Question: An application publishes all order events to an Amazon SNS topic. Several AWS Lambda functions subscribe to the topic through their own Amazon SQS queues. The shipping function needs only events where the shipping attribute is express, but it currently receives every event and discards 90% of them. What should the developer do to optimize the messaging?
- A. Create a separate SNS topic for each attribute value and update the publisher to send each event to multiple topics.
- B. Add a subscription filter policy to the shipping queue's subscription that matches the express value of the shipping attribute.
- C. Increase the batch size of the shipping function's event source mapping.
- D. Replace the SNS topic with a single SQS queue that all functions poll.

Xem đáp án **Đáp án: B** · *Domain 4.3 – tối ưu messaging (SNS fan-out)* - ✅ B: **SNS subscription filter policy** (theo message attributes hoặc message body) giúp mỗi subscriber chỉ nhận message phù hợp, giảm số message vào SQS, số lần invoke và chi phí. Mẫu **SNS → nhiều SQS** chính là fan-out. - ❌ A: phải sửa publisher, phức tạp. - ❌ C: vẫn nhận 100% message. - ❌ D: mỗi message chỉ đến **một** consumer, làm hỏng fan-out.

Câu 65

Question: A product catalog API reads items from an Amazon DynamoDB table. The same popular items are read thousands of times per second, and the application requires microsecond read latency. The developer wants to implement caching with the LEAST changes to the existing DynamoDB API calls in the code. What should the developer do?
- A. Add an Amazon ElastiCache (Redis OSS) cluster and implement a lazy-loading cache in the application code.
- B. Add an Amazon CloudFront distribution in front of the DynamoDB table.
- C. Increase the table's read capacity units.
- D. Create a DynamoDB Accelerator (DAX) cluster and use the DAX client, which is API-compatible with DynamoDB.

Xem đáp án **Đáp án: D** · *Domain 4.3 – caching* - ✅ D: **DAX** là cache in-memory dành riêng cho DynamoDB, độ trễ **microsecond**, client **tương thích API** nên chỉ cần đổi client. Là write-through cache cho item và cache cho query. Chỉ hỗ trợ đọc eventually consistent. - ❌ A: ElastiCache phải viết logic cache (lazy loading hoặc write-through), sửa code nhiều. - ❌ B: CloudFront không đặt trước DynamoDB được. - ❌ C: tăng RCU không đạt được độ trễ microsecond.

Mẹo nhớ theo chủ đề

Mới trong DVA-C03: AI & bảo mật AI

  • Gọi nhiều model qua một format chung, hội thoại nhiều lượt → Bedrock Converse API (ConverseStream để stream).
  • ThrottlingException → retry backoff + jitter và cross-Region inference profile.
  • Chỉ cho gọi một model → IAM bedrock:InvokeModel trên ARN của foundation model.
  • Không đi qua internet → interface VPC endpoint (PrivateLink) cho bedrock-runtime. Bedrock không dùng prompt/response để train model.
  • Chặn chủ đề, che PII, chống prompt injection → Bedrock Guardrails (denied topics, sensitive info filter MASK/BLOCK, prompt attack filter). Dùng ApplyGuardrail để áp guardrail cho cả model ngoài Bedrock.
  • Hành động nhạy cảm cần người duyệt → user confirmation / return of control (human-in-the-loop).
  • Cô lập session của agent → AgentCore Runtime (microVM cho mỗi session). Credential để agent gọi tool → AgentCore Identity. Biến API/Lambda thành tool MCP → AgentCore Gateway.
  • PII trong log (cả model invocation logging) → CloudWatch Logs data protection policy + quyền logs:Unmask.
  • Ngoài phạm vi thi: chọn FM, prompt engineering, thiết kế RAG, thiết kế guardrail/governance, SageMaker AI, Strands Agents.

Kiro (AI-assisted development)

  • Requirements → design → tasks, duyệt trước khi code → Specs.
  • Quy ước lâu dài cho agent → Steering (.kiro/steering/*.md).
  • Tự động khi lưu/tạo file (sinh test, cập nhật docs) → Agent hooks.

Container (mới nhấn mạnh trong C03)

  • Dọn image cũ/untagged → ECR lifecycle policy. Chống ghi đè tag → tag immutability. Deploy đúng image → commit SHA / digest.
  • Pull image, ghi log, lấy secret → task execution role. Code gọi dịch vụ AWS → task role.
  • Rolling update không giảm capacity → minimumHealthyPercent=100, maximumPercent=200. Tự rollback → deployment circuit breaker.
  • Chưa sẵn sàng thì không nhận traffic → readiness probe. Treo thì restart → liveness probe.

Lambda

  • Gắn VPC muốn ra internet → NAT gateway. Gọi DynamoDB/S3 → gateway endpoint. Gọi dịch vụ khác → interface endpoint.
  • Telemetry chạy song song với function → extension (dạng layer). Package lớn hơn 250 MB → container image (10 GB).
  • Async success/failure kèm context → Destinations. Một message lỗi làm hỏng cả batch → ReportBatchItemFailures. Bớt invoke thừa → ESM filter criteria.
  • Java cold start, rẻ → SnapStart. Burst kết nối DB → RDS Proxy. Chọn memory → Compute Optimizer / Power Tuning.
  • Log JSON + log level không cần code → advanced logging controls. Custom metric không gọi API → EMF.

DynamoDB

  • GSI chỉ eventually consistent. Cần read-after-write thì đọc bảng gốc với ConsistentRead.
  • Tránh lost update → optimistic locking (version + ConditionExpression).
  • Mỗi user chỉ thấy item của mình → dynamodb:LeadingKeys. Ẩn cột nhạy cảm → dynamodb:Attributes.
  • Cache microsecond, ít sửa code → DAX.

Streaming & messaging

  • Ghi stream vào S3 dạng Parquet, không viết consumer → Data Firehose. Shard nóng → partition key cardinality cao.
  • SNS → SQS mà body có Type, Message → parse 2 lần hoặc bật raw message delivery.
  • Nhiều consumer cho event S3, lọc theo nội dung → EventBridge.
  • Subscriber chỉ cần một phần message → SNS filter policy.

Security

  • Login Google, upload vào prefix riêng → identity pool + ${cognito-identity.amazonaws.com:sub}.
  • CLI + MFA → sts get-session-token --serial-number --token-code.
  • Presigned URL chết sớm → credential tạm dùng để ký đã hết hạn. Nhiều file qua CloudFront → signed cookies + OAC.
  • IAM auth trên API Gateway → ký SigV4. Cross-account → trust policy (B) + sts:AssumeRole (A).
  • Dữ liệu lớn hơn 4 KB với KMS → GenerateDataKey (envelope). mTLS nội bộ → AWS Private CA. Cert cho CloudFront → us-east-1.
  • Shell vào EC2 không cần port 22 hay SSH key → Session Manager. Secret gọi nhiều lần → Parameters and Secrets Lambda Extension.

Testing & deployment

  • Test template CDK → assertions (Template.fromStack). Event mẫu → sam local generate-event + sam local invoke -e.
  • Môi trường cho mỗi branch/PR frontend → Amplify branch auto-detection + PR previews.
  • Feature flag + rollout dần + rollback theo alarm → AppConfig.
  • Nhiều API trên một domain → custom domain + API mappings (base path).
  • SAM canary + rollback → AutoPublishAlias + DeploymentPreference (Canary10Percent10Minutes, Alarms).
  • Pipeline chỉ chạy khi có tag → CodePipeline V2 trigger filter. Cần người duyệt → manual approval.
  • CloudFormation tự rollback theo alarm → rollback triggers (MonitoringTimeInMinutes). Tìm nguyên nhân → sự kiện CREATE_FAILED đầu tiên.

Troubleshooting

  • Top lỗi trong log → Logs Insights (stats count(*) by … | sort | limit).
  • AI tự phân tích sự cố từ alarm → CloudWatch investigations.
  • Cảnh báo khi gần chạm quota → alarm SERVICE_QUOTA() + SNS. Báo khi deploy xong → EventBridge rule + SNS.
  • Tìm trace theo field → annotation (được index), không phải metadata.
