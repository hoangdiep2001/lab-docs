AWS DOP-C02 (DevOps Engineer – Professional) – Practice Exam 01 (75 câu, mức khó) – Đề + Đáp án + Phân tích

Đề tự soạn bám sát exam guide DOP-C02 chính thức. Độ khó cao hơn đề thật một chút: kịch bản dài, nhiều đáp án "gần đúng", nhiều câu chọn 2–3.
Đề thật: 75 câu (65 tính điểm + 10 không tính), 180 phút, đậu khi đạt 750/1000. Trung bình khoảng 2 phút 20 giây mỗi câu: đọc câu hỏi cuối đề trước, gạch chân ràng buộc (LEAST overhead, MOST secure, minimize downtime…).
Mỗi câu gồm: Question (tiếng Anh) → bấm Xem đáp án để xem đáp án + domain + phân tích (tiếng Việt).

Câu 1 (chọn 3)

Question: A company uses AWS CodePipeline in a central tooling account to deploy AWS CloudFormation stacks to a production account. The pipeline's artifact store is an Amazon S3 bucket in the tooling account that is encrypted with the AWS managed key (aws/s3). The deploy stage fails with an access denied error when CloudFormation in the production account tries to read the template artifact. Which combination of steps should a DevOps engineer take to resolve the issue? (Choose three.)
- A. Create a customer managed AWS KMS key in the tooling account. Configure the pipeline to use the key for the artifact store, and add the production account's cross-account role to the key policy.
- B. Replicate the artifact bucket to the production account by using S3 Cross-Region Replication.
- C. Add a bucket policy to the artifact bucket that allows the production account's cross-account role to get objects.
- D. Grant the production account access to the aws/s3 AWS managed key by editing its key policy.
- E. Create an IAM role in the production account that the pipeline assumes for the deploy action, and pass a CloudFormation service role in the production account to the action.
- F. Create an IAM user in the production account and store its access keys as pipeline variables.

Xem đáp án **Đáp án: A, C, E** · *Domain 1.1 – pipeline đa account* - ✅ A: artifact cross-account **bắt buộc dùng customer managed key (CMK)**, vì key policy của AWS managed key **không sửa được**. - ✅ C: bucket policy cho phép role bên prod đọc artifact. - ✅ E: action deploy dùng `RoleArn` để assume role bên prod. Role đó truyền **CloudFormation service role** (cùng account prod) cho CloudFormation. - ❌ B: phức tạp, không cần thiết. - ❌ D: không sửa được key policy của AWS managed key. - ❌ F: dùng credential dài hạn.

Câu 2

Question: An AWS CodeBuild project builds a Node.js application that pulls private packages by using an npm access token. A security audit found the token in plaintext in the CodeBuild project's environment variable configuration. The token must be rotated every 30 days, must never appear in the project configuration or in the build logs, and the solution must require the LEAST operational overhead. What should the DevOps engineer do?
- A. Store the token in an AWS Systems Manager Parameter Store String parameter, and reference it in the buildspec under env/parameter-store.
- B. Store the token in an encrypted file in the source repository, and decrypt it in the pre_build phase with an AWS KMS key.
- C. Pass the token to the build as a pipeline variable from AWS CodePipeline.
- D. Store the token in AWS Secrets Manager with a rotation schedule, reference it in the buildspec under env/secrets-manager, and grant the CodeBuild service role secretsmanager:GetSecretValue on the secret.

Xem đáp án **Đáp án: D** · *Domain 1.1 – quản lý secret khi build* - ✅ D: Secrets Manager có **rotation** (dùng Lambda). Buildspec viết `env: secrets-manager: NPM_TOKEN: arn:…:secret:npm:token`. CodeBuild **tự che (mask)** giá trị secret trong log. - ❌ A: tham số kiểu **String** không được mã hóa, và Parameter Store **không có rotation** tích hợp. - ❌ B: secret nằm trong repo, và tự quản lý rất cực. - ❌ C: pipeline variable hiển thị rõ ràng trong lịch sử thực thi.

Câu 3

Question: A company has 40 development teams in separate AWS accounts in AWS Organizations. The company wants a single, centrally managed package repository for npm and PyPI packages. Public packages must be cached so that builds continue to work if the public registries are unavailable. All accounts in the organization must be able to read packages, and no account outside the organization can have access. Which solution meets these requirements with the LEAST operational overhead?
- A. Create an Amazon S3 bucket in each account and sync packages with a nightly AWS Lambda function.
- B. Create an AWS CodeArtifact domain in a shared services account. Create a repository with external connections to the public npm and PyPI registries, and use it as an upstream repository for team repositories. Add a domain policy that allows access when aws:PrincipalOrgID matches the organization ID.
- C. Create a CodeArtifact domain in every account with external connections, and share packages with AWS RAM.
- D. Run a self-managed Nexus repository on Amazon EC2 behind a Network Load Balancer, and allow the organization's CIDR ranges.

Xem đáp án **Đáp án: B** · *Domain 1.3 – artifact repository* - ✅ B: CodeArtifact theo mô hình **domain** (tập trung, đi kèm KMS key), **repository** và **upstream**. **External connection** cache package public, nên khi registry public sập vẫn build được. **Domain policy** dùng `aws:PrincipalOrgID` để chia sẻ cho cả tổ chức. - ❌ A, D: tự vận hành nhiều. - ❌ C: mỗi account một domain là phân tán, không tập trung. Sharing qua RAM cũng không phải cách CodeArtifact chia sẻ.

Câu 4

Question: A company must produce a hardened Amazon Linux AMI every month and whenever a new security patch is released for an installed package. Each AMI must pass automated tests before use, must be distributed to three AWS Regions and to 12 accounts, and the launch templates used by the Auto Scaling groups in those accounts must be updated automatically to reference the new AMI. Which solution meets these requirements with the LEAST custom code?
- A. Use AWS Systems Manager Automation with the AWS-UpdateLinuxAmi runbook, and use a Lambda function to copy and share the AMI and update the launch templates.
- B. Use Packer in AWS CodeBuild, and use CloudFormation StackSets to update the launch templates.
- C. Create an EC2 Image Builder pipeline with build and test components, a schedule that runs monthly and when dependency updates are available, and a distribution configuration that targets the Regions and accounts and updates the specified launch templates.
- D. Take a snapshot of a manually patched instance every month and share it with the accounts.

Xem đáp án **Đáp án: C** · *Domain 1.3 – tự động hóa build AMI/container image* - ✅ C: **Image Builder** gồm recipe, các component build và test, lịch chạy (cron cùng điều kiện "chỉ chạy khi có cập nhật dependency"), **distribution settings** (copy sang nhiều Region, chia sẻ hoặc copy cho account khác, **cập nhật launch template**). Gần như không phải viết code. - ❌ A: phải tự viết code phân phối AMI. - ❌ B: phải tự viết code. - ❌ D: thủ công, không có test.

Câu 5

Question: An application is deployed to an Amazon EC2 fleet by using AWS CodeDeploy in-place deployments. A developer accidentally committed a broken script for the ApplicationStop lifecycle event, and that revision was deployed successfully. Every subsequent deployment, including deployments of fixed revisions, now fails at the ApplicationStop event. What should the DevOps engineer do to deploy the fixed revision?
- A. Create a new deployment of the fixed revision with the option to ignore ApplicationStop failures (--ignore-application-stop-failures).
- B. Move the ApplicationStop script to the BeforeInstall hook in the fixed revision's AppSpec file.
- C. Delete the deployment group and create it again.
- D. Reinstall the CodeDeploy agent on every instance.

Xem đáp án **Đáp án: A** · *Domain 1.4 – troubleshoot deployment* - ✅ A: **ApplicationStop chạy script của revision thành công lần trước** (vì đó là app đang chạy). Script lỗi đã nằm trên máy, nên sửa revision mới không có tác dụng. Phải bỏ qua lỗi ApplicationStop cho lần deploy này. - ❌ B: ApplicationStop vẫn chạy script cũ trước khi đến BeforeInstall. - ❌ C, D: không xóa được script cũ mà agent đang dùng.

Câu 6

Question: A company runs a containerized service on Amazon ECS with an Application Load Balancer and uses AWS CodeDeploy blue/green deployments. The company wants an automated integration test suite to run against the new (green) task set by using real infrastructure before any production traffic is shifted. If the tests fail, the deployment must roll back automatically. What should the DevOps engineer do?
- A. Run the tests in a CodeBuild stage after the deployment completes, and redeploy the previous revision if they fail.
- B. Configure a Route 53 weighted record that sends 5% of traffic to the green task set.
- C. Use the BeforeInstall hook to run the tests against the blue task set.
- D. Configure a test listener on the ALB for the deployment group, and add a Lambda function to the AfterAllowTestTraffic hook that runs the tests through the test listener and reports Failed to CodeDeploy when tests fail.

Xem đáp án **Đáp án: D** · *Domain 1.2 – test trong pipeline* - ✅ D: ECS blue/green hỗ trợ **test listener** (ví dụ cổng 8080) để gửi traffic thử tới green. Thứ tự hook: `BeforeInstall → AfterInstall → AfterAllowTestTraffic → BeforeAllowTraffic → AfterAllowTraffic`. Lambda hook gọi `PutLifecycleEventHookExecutionStatus` với trạng thái Failed sẽ kích hoạt **rollback**. - ❌ A: test sau khi production đã nhận traffic. - ❌ B: dùng traffic thật. - ❌ C: test nhầm vào bản cũ.

Câu 7

Question: A CodeBuild project runs an end-to-end test suite of 4,000 tests that takes 3 hours to complete sequentially. The company wants to reduce the test time in the pipeline to under 30 minutes without managing additional infrastructure. What should the DevOps engineer do?
- A. Increase the CodeBuild compute type to the largest available size.
- B. Configure a CodeBuild batch build that uses build-fanout to run the test suite in parallel across multiple build environments, splitting the tests across the parallel builds.
- C. Run the tests on an Amazon EC2 Auto Scaling group that scales on CPU utilization.
- D. Create 10 separate CodeBuild projects and 10 pipeline stages that run one after another.

Xem đáp án **Đáp án: B** · *Domain 1.2 – test ở quy mô lớn* - ✅ B: **batch build** có các kiểu `build-list`, `build-matrix`, `build-graph` và **`build-fanout`** (chia test chạy song song, có công cụ `codebuild-tests-run` để chia theo file hoặc thời gian). Có thể gộp kết quả báo cáo. - ❌ A: test đơn luồng thì không nhanh hơn nhiều. - ❌ C: phải tự quản lý hạ tầng. - ❌ D: các stage chạy nối tiếp nhau, vẫn chậm.

Câu 8

Question: A buildspec file contains the command npm test | tee test-output.txt in the build phase. Several builds were marked as SUCCEEDED in CodeBuild even though the test output shows failed tests, so broken code reached production. What is the cause, and how should the DevOps engineer fix it?
- A. CodeBuild ignores exit codes in the build phase. Move the command to the post_build phase.
- B. The tee command writes to a file that CodeBuild cannot read. Write the output to /tmp instead.
- C. The exit status of a pipeline is the exit status of the last command (tee), which succeeds. Enable set -o pipefail (or check PIPESTATUS) so that a failing npm test causes a non-zero exit code.
- D. CodeBuild marks a build as failed only if a report group is configured. Add a report group.

Xem đáp án **Đáp án: C** · *Domain 1.2 – đo app health bằng exit code* - ✅ C: CodeBuild đánh giá **exit code** của từng lệnh. Với pipe, exit code là của lệnh cuối cùng (`tee` luôn trả về 0), nên lỗi bị "nuốt". Dùng `set -o pipefail` hoặc tách lệnh. Thêm `on-failure: ABORT` để dừng phase ngay. - ❌ A: CodeBuild vẫn tính exit code ở phase build. Sai. - ❌ B: không liên quan. - ❌ D: report group không quyết định trạng thái build.

Question: A team wants to see unit test results and code coverage trends for every build in the AWS Management Console, without operating external tools. The tests produce JUnit XML results and Cobertura XML coverage files. What should the DevOps engineer do?
- A. Add a reports section to the buildspec that defines a test report group with file-format JUNITXML and a code coverage report group with file-format COBERTURAXML.
- B. Upload the XML files to Amazon S3 and query them with Amazon Athena.
- C. Publish the results as custom CloudWatch metrics by using PutMetricData.
- D. Store the files as build artifacts and download them after each build.

Xem đáp án **Đáp án: A** · *Domain 1.2 – unit test & code coverage tự động* - ✅ A: **CodeBuild reports**. Test report hỗ trợ JUnit, NUnit, TestNG, Cucumber, Visual Studio TRX. Coverage hỗ trợ **JaCoCo, Cobertura, Clover, SimpleCov**. Console hiển thị xu hướng (pass rate, line/branch coverage). - ❌ B, C, D: tự dựng, tốn công.

Câu 10

Question: A company stores code in GitHub. The DevOps team wants a CodeBuild project to run unit tests automatically whenever a pull request that targets the main branch is opened, updated, or reopened, and the build result must be shown on the pull request. Builds must not run for pull requests that target other branches. What should the DevOps engineer configure?
- A. A CodePipeline pipeline with a GitHub source action on the main branch
- B. An Amazon EventBridge rule that runs the build every 5 minutes

Question: Amazon GuardDuty generates a high-severity CryptoCurrency:EC2/BitcoinTool.B!DNS finding for a production Amazon EC2 instance. Mẹo nhớ theo chủ đề

Pipeline & artifact (Domain 1)

  • Cross-account pipeline → CMK (không dùng aws/s3) + bucket policy + role bên đích (RoleArn của action) + CloudFormation service role.
  • Secret khi build → env: secrets-manager (có rotation, che trong log). Parameter Store String là không mã hóa.
  • Repo package dùng chung cho tổ chức → CodeArtifact domain + upstream + external connection, domain policy aws:PrincipalOrgID.
  • Docker Hub rate limit → ECR pull through cache. AMI vàng nhiều Region/account → Image Builder distribution.
  • Test trước khi chuyển traffic (ECS blue/green) → test listener + AfterAllowTestTraffic.
  • Lambda action trong pipeline → bắt buộc gọi PutJobSuccessResult/PutJobFailureResult.
  • cmd | tee nuốt lỗi → set -o pipefail. Test chạy lâu → batch build-fanout. Báo cáo test và coverage → reports: (JUNITXML, COBERTURAXML).
  • ApplicationStop chạy script của revision cũ → --ignore-application-stop-failures.
  • Monorepo → V2 trigger file path filter. Build once, promote same artifact.
  • Lambda image theo tag → phải update-function-code (Lambda gắn với digest).
  • Beanstalk: canary theo % → traffic splitting. Có ASG tạm, rollback nhanh → immutable.

IaC & governance (Domain 2)

  • Account mới trong OU tự nhận stack → StackSets service-managed + automatic deployment. Chạy nhanh → MaxConcurrent…, FailureTolerance…, PARALLEL.
  • Custom resource treo → luôn gửi phản hồi về ResponseURL (kể cả khi Delete hoặc lỗi).
  • Chặn replace DB → stack policy + UpdateReplacePolicy (DeletionPolicy chỉ áp dụng khi xóa).
  • Ép chuẩn trong CDK → Aspects / cdk-nag. Dev tự phục vụ mà không có quyền trực tiếp → Service Catalog + launch constraint.
  • Chặn trước khi provision → proactive control (CloudFormation Hooks). Preventive = SCP. Detective = Config.
  • Tùy biến account (CloudFormation) → CfCT. Dùng Terraform → AFT.
  • SCP deny kèm ngoại lệ → ArnNotLike aws:PrincipalArn. Giới hạn Region → NotAction các dịch vụ global. SCP không áp dụng cho management account.
  • Patch cả tổ chức → Quick Setup patch policy. Desired state → State Manager association. Phần mềm cấm → Inventory + Config rule.

Resilience (Domain 3)

  • Aurora global: diễn tập không mất dữ liệu → switchover. Region chính sập thật → failover (allow data loss).
  • Active-active nhiều Region → DynamoDB global tables (last writer wins).
  • Health check cho tài nguyên private → Route 53 health check theo CloudWatch alarm.
  • RTO/RPO tính bằng giờ → backup & restore (AWS Backup cross-Region copy). Phút → pilot light hoặc warm standby. Gần 0 → multi-site.
  • ASG không thay instance lỗi app → health check type ELB. Worker SQS → backlog per instance.
  • ECS task kẹt PROVISIONING → capacity provider managed scaling. EKS pod Pending → Karpenter / Auto Mode.
  • UDP, IP tĩnh, failover vài giây → Global Accelerator. S3 SLA 15 phút → RTC. Object có sẵn → Batch Replication.
  • Instance đơn lẻ phải giữ ID, IP → EC2 auto recovery (lỗi system status check).

Monitoring (Domain 4)

  • Xem metric, log, trace của nhiều account mà không copy → cross-account observability (sink/link).
  • Đẩy metric ra ngoài liên tục → metric streams + Firehose.
  • Mã hóa log group bằng CMK → key policy cho logs.<region>.amazonaws.com.
  • Lưu 30 ngày rồi 7 năm → retention + subscription → Firehose → S3 → Deep Archive.
  • Traffic theo mùa vụ → anomaly detection. Giảm nhiễu → composite alarm.
  • Metric theo từng process → CloudWatch agent procstat. X-Ray trên Fargate → sidecar + task role.
  • SQL trên CloudTrail cả tổ chức, bất biến → CloudTrail Lake. Phân tích log trong vài giây → subscription → Kinesis Data Streams → Lambda.

Incident (Domain 5)

  • EC2 retirement → Health event → EventBridge → SSM Automation (stop/start).
  • Tự sửa cấu hình sai → Config rule + auto remediation SSM. Trung tâm xử lý sự cố → OpsCenter.
  • ECS task bị thay liên tục khi warm-up → health check grace period. Lấy log trước khi terminate → lifecycle hook.
  • Pod dùng role của node → thiếu IRSA annotation/OIDC provider hoặc Pod Identity association.
  • Kiểm tra luồng người dùng 24/7 → Synthetics canary. Chờ người duyệt nhiều ngày → waitForTaskToken.
  • Thứ tự theo khách hàng + song song → FIFO + message group ID. UPDATE_ROLLBACK_FAILED → ContinueUpdateRollback + ResourcesToSkip.

Security (Domain 6)

  • Cho dev tạo role mà không leo quyền → permissions boundary bắt buộc (iam:PermissionsBoundary).
  • Quyền theo project mà không sửa policy → ABAC (aws:ResourceTag = aws:PrincipalTag).
  • Nhân viên đăng nhập bằng IdP, nhiều account → Identity Center + SCIM + permission sets.
  • Rotation không gián đoạn → alternating users. Key bị lộ → Health AWS_RISK_CREDENTIALS_EXPOSED → EventBridge.
  • Security Hub cả tổ chức → delegated admin + central configuration. Dữ liệu nhạy cảm trong S3 → Macie automated discovery.
  • WAF cho mọi ALB và CloudFront → Firewall Manager. Lọc egress theo domain → Network Firewall.
  • HSM single-tenant + tích hợp KMS → CloudHSM custom key store. Truy cập từ ngoài tổ chức → Access Analyzer.
  • GuardDuty finding → cô lập (SG) + snapshot + Detective. Log không thể sửa hoặc xóa → log file validation + Object Lock compliance.
