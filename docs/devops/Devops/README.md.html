⚠️ 7 ngày cho bài thi Professional là rất gấp. Kế hoạch 7 ngày giả định bạn đã nắm vững kiến thức DVA-C03, đã từng vận hành multi-account thật và học khoảng 7–8 giờ mỗi ngày. Riêng Lab 0–13 đã khoảng 23 giờ (thực tế thường 1,5–2 lần vì debug IAM/mạng).

Khuyến nghị mặc định: 10–14 ngày. Làm theo lịch 7 ngày bên dưới nhưng mỗi "ngày" trải thành 1,5–2 ngày, chèn các lab bổ sung (cột "Lab bổ sung" ở mỗi ngày) và luyện thêm ≥ 200 câu tiếng Anh bấm giờ (Official Practice Exam + Tutorials Dojo). Chỉ giữ 7 ngày khi đề chẩn đoán ngày 1 đã ≥ 70%.

📌 Đề DOP-C02 soạn chủ yếu năm 2023. Đề thật vẫn hỏi các dịch vụ/tính năng đã đổi trạng thái như thể chúng còn nguyên: OpsWorks (EOL 05/2024), Inspector Classic (assessment template), CodeDeploy cho blue/green ECS. CodeCommit từng ngừng nhận khách mới (07/2024) nhưng đã trở lại GA từ 24/11/2025, nên cứ coi là dịch vụ bình thường. Xem mục Cảnh báo "đề cũ" trong cheat sheet.

Cheat sheet (high-yield)

D1: SDLC Automation

CodeBuild
- buildspec.yml có các phase install → pre_build → build → post_build, cùng reports (JUnit, Cucumber, Cobertura/JaCoCo coverage), artifacts, cache.
- Build Docker image cần bật privileged mode. Truy cập tài nguyên private (RDS...) cần cấu hình VPC.
- Build khi có PR: dùng webhook filter (PULL_REQUEST_CREATED, PULL_REQUEST_UPDATED). Có batch build.
- Exit code khác 0 thì build fail, đây là cách đo "app health theo exit code".

CodeDeploy
- Agent ghi log tại /var/log/aws/codedeploy-agent/. Có thể cài agent qua SSM Distributor.
- Instance cần instance profile có quyền đọc S3 (nơi để revision).
- Deployment config cho EC2: OneAtATime, HalfAtATime, AllAtOnce, hoặc custom (minimum healthy hosts).
- Blue/green trên EC2: tạo bản sao ASG mới, chuyển ELB sang, rồi terminate instance cũ (có thể đặt thời gian chờ).
- Auto rollback khi deploy lỗi hoặc khi alarm kích hoạt. Rollback là một deployment mới dùng lại revision cũ.
- Script ApplicationStop của revision cũ bị lỗi: dùng --ignore-application-stop-failures.
- Nhận thông báo sự kiện deploy: dùng trigger (SNS) hoặc EventBridge.

CodePipeline
- Mỗi stage gồm nhiều action, chạy tuần tự (theo runOrder) hoặc song song.
- Có manual approval. Pipeline V2 hỗ trợ trigger theo git tag hoặc branch, biến pipeline, và rollback stage.
- Cross-account:
1. Artifact bucket mã hoá bằng KMS CMK có key policy cho phép account đích.
2. Bucket policy cho account đích.
3. Role ở account đích để pipeline assume.
4. CloudFormation deploy role ở account đích.

CodeArtifact
- Cấu trúc: domain → repository → upstream → external connection (npmjs, PyPI, Maven Central).
- aws codeartifact login --tool npm|pip|twine, token mặc định hết hạn sau 12 giờ.
- Quyền dùng chung qua domain policy và repository policy (cross-account).

ECR
- Lifecycle policy, tag immutability, scan (basic hoặc enhanced với Inspector).
- Replication cross-Region/cross-account. Cấp quyền cross-account bằng repository policy. Pull-through cache.

EC2 Image Builder
- Pipeline gồm recipe (base image + component) → test → distribution (copy AMI sang region/account khác) → chạy theo lịch.
- Sau khi có AMI mới thì cập nhật Launch Template và chạy ASG Instance Refresh.

CodePipeline V2: tính năng mới hay vào đề
- Trigger lọc theo branch, file path, git tag, pull request event.
- Stage conditions: Entry (trước khi vào stage, ví dụ chặn deploy khi có CloudWatch alarm đang bật, hoặc ngoài khung giờ cho phép), On Success, On Failure (tự rollback stage về lần chạy thành công gần nhất, hoặc retry).
- Execution mode: SUPERSEDED (mặc định, lần chạy mới thay lần cũ), QUEUED (chạy lần lượt), PARALLEL.
- Có action deploy trực tiếp cho ECS, EKS, Lambda, EC2, và action chạy lệnh (Commands).

ECS deployment (cập nhật 2025)
- Rolling update + deployment circuit breaker (enable: true, rollback: true): task mới không lên được (health check fail, crash) thì ECS tự dừng và rollback về bản cũ. Có thể gắn thêm CloudWatch alarm để rollback.
- Blue/green, canary, linear có sẵn trong ECS (từ 07/2025 và 10/2025): không cần CodeDeploy. Có lifecycle hooks (Lambda) để test trước khi chuyển traffic, có bake time, rollback theo alarm. Dùng ALB/NLB, Service Connect hoặc VPC Lattice.
- Blue/green bằng CodeDeploy vẫn được dùng (đề cũ hay hỏi): cần 2 target group, test listener, hooks AfterAllowTestTraffic.
- Lỗi task: CannotPullContainerError (execution role, không có đường mạng tới ECR, thiếu VPC endpoint ecr.api, ecr.dkr, S3 gateway endpoint), ResourceInitializationError (không lấy được secret hoặc log).

Mutable và immutable
- Mutable: in-place, rolling.
- Immutable: blue/green, immutable của Beanstalk, AMI mới + instance refresh. Rollback dễ hơn, ít bị lệch cấu hình (drift).

Elastic Beanstalk
- Các policy deploy: All at once, Rolling, Rolling with additional batch, Immutable, Traffic splitting (canary). Blue/green bằng Swap environment URLs.
- Cấu hình nằm trong .ebextensions và .platform/hooks.

D2: Configuration Management & IaC

CloudFormation
- StackSets:
- Self-managed: tự tạo role AWSCloudFormationStackSetAdministrationRole/ExecutionRole.
- Service-managed: dùng Organizations; auto-deploy khi có account mới vào OU.
- Điều khiển tốc độ bằng MaxConcurrent và FailureTolerance. Có delegated admin.
- Change set: xem trước thay đổi. Drift detection: phát hiện ai đó sửa tay tài nguyên.
- Custom resource: Lambda nhận ServiceToken, phải gửi kết quả về pre-signed S3 URL. Nếu không gửi, stack treo tới khoảng 1 giờ.
- cfn-init đọc AWS::CloudFormation::Init. cfn-signal + CreationPolicy/WaitCondition để báo instance đã sẵn sàng. cfn-hup phát hiện metadata thay đổi và cấu hình lại.
- UpdatePolicy cho ASG: AutoScalingRollingUpdate (thay từng đợt) hoặc AutoScalingReplacingUpdate (tạo ASG mới).
- DeletionPolicy (Retain, Snapshot, Delete) và UpdateReplacePolicy. Stack policy chặn update một số resource. Bật termination protection.
- Stack kẹt ở UPDATE_ROLLBACK_FAILED: dùng continue-update-rollback (có thể skip resource).
- Mở rộng và kiểm soát template: Modules (tái sử dụng), Macros (biến đổi template), Hooks (kiểm tra trước khi tạo resource), CloudFormation Guard (policy-as-code).
- Lấy giá trị động: {{resolve:ssm:...}}, {{resolve:secretsmanager:...}}.

CDK
- Construct L1/L2/L3. Chạy cdk bootstrap (một lần cho mỗi account/region), sau đó cdk deploy.
- CDK Pipelines là pipeline tự cập nhật (self-mutating).
- Aspects dùng để áp quy tắc lên mọi construct. cdk-nag để kiểm tra compliance.

Service Catalog
- Gồm portfolio và product (template CloudFormation).
- Launch constraint (IAM role): user không cần quyền trên các resource bên dưới. Có thể chia sẻ portfolio cho OU.

Organizations
- SCP không cấp quyền, chỉ đặt giới hạn tối đa. SCP không ảnh hưởng tới management account. Ngoài SCP còn có tag policy, backup policy, RCP (resource control policy).
- Delegated administrator cho GuardDuty, Security Hub, Config, StackSets...

Control Tower
- Landing zone gồm các account Management, Log Archive, Audit.
- Controls: Preventive (SCP/RCP), Detective (Config rule), Proactive (CloudFormation Hooks).
- Account Factory (dùng Service Catalog), AFT (Account Factory for Terraform), CfCT (Customizations for Control Tower). Drift của landing zone sửa bằng Repair.

Systems Manager
- Run Command: chạy lệnh ngay một lần.
- State Manager: duy trì trạng thái mong muốn theo lịch (association).
- Automation: chạy runbook nhiều bước, dùng cho remediation.
- Patch Manager: patch baseline, tag Patch Group, chạy AWS-RunPatchBaseline trong Maintenance Window. Quick Setup patch policy áp dụng cho cả Organizations.
- Inventory: thu thập danh sách phần mềm. Compliance: báo cáo patch/association.
- Session Manager: truy cập máy không cần SSH hay bastion, log vào S3/CloudWatch.
- OpsCenter: OpsItems. Distributor: phân phối package.
- Instance cần SSM Agent + instance profile AmazonSSMManagedInstanceCore + đường mạng tới endpoint SSM (VPC endpoint nếu ở subnet private).

AWS Config
- Rule kích hoạt theo thay đổi (change-triggered) hoặc định kỳ (periodic). Rule có thể là managed, custom Lambda, hoặc custom Guard.
- Remediation chạy SSM Automation (tự động hoặc thủ công).
- Conformance pack là bộ rule đóng gói. Aggregator gom dữ liệu nhiều account/region.

OpsWorks: đã hết hỗ trợ (Stacks EOL 26/05/2024). Khi đề có phương án hiện đại thì ưu tiên SSM State Manager. Nhưng đề cũ vẫn có thể hỏi OpsWorks như dịch vụ sống: stack → layer → instance, lifecycle event (Setup, Configure, Deploy, Undeploy, Shutdown; Configure chạy trên mọi instance khi có instance vào/ra stack), Chef recipe, auto-healing, instance kiểu 24/7, time-based, load-based.

D3: Resilience & DR

Chiến lược RTO / RPO Chi phí Mô tả
Backup & Restore Giờ $ Chỉ có backup, cần khôi phục mới chạy được
Pilot Light Hàng chục phút $$ Dữ liệu được replicate, phần core tắt hoặc rất nhỏ, khi cần thì bật và scale lên
Warm Standby Phút $$$ Có bản sao chạy thu nhỏ, khi cần thì scale lên
Multi-site Active/Active ~0 $$$$ Cả 2 region đều phục vụ traffic
  • RTO = thời gian chấp nhận được để hệ thống phục hồi. RPO = lượng dữ liệu tối đa có thể mất (tính theo thời gian).
  • Aurora Global Database: replicate sang region khác với độ trễ < 1 giây. Có managed switchover/failover. Có write forwarding.
  • RDS Multi-AZ: failover đồng bộ trong cùng region, kiểm thử bằng reboot --force-failover. Read replica cross-Region có thể promote thành DB chính.
  • DynamoDB Global Tables: multi-active, nhiều region cùng ghi. S3 CRR: cần bật versioning; dùng RTC nếu cần SLA 15 phút. Muốn chuyển region dễ dàng thì dùng S3 Multi-Region Access Points.
  • Route 53:
  • Routing policy: failover, latency, weighted, geolocation, geoproximity, multivalue.
  • Health check loại endpoint, calculated, hoặc CloudWatch alarm (dùng cho tài nguyên private).
  • Application Recovery Controller (ARC) để điều khiển failover chủ động.
  • CloudFront origin group: failover sang origin phụ khi gặp lỗi 5xx/4xx.
  • AWS Backup: backup plan có copy cross-Region/cross-account, Vault Lock (WORM), tạo backup policy từ Organizations.
  • ELB: cross-zone (ALB mặc định bật ở cấp LB nhưng tắt được ở cấp target group từ 11/2022; NLB/GWLB mặc định tắt, bật ở cấp LB hoặc target group, NLB tính phí data transfer giữa AZ khi bật), health check, deregistration delay.
  • ASG:
  • Health check type ELB để thay cả instance bị lỗi ở tầng ứng dụng.
  • Lifecycle hook cho phép chạy script khi launch/terminate. Warm pool giúp scale nhanh. Instance refresh.
  • Có thể suspend process (ví dụ tạm tắt ReplaceUnhealthy khi debug).
  • Scaling policy: target tracking, step, scheduled, predictive.
  • Kiểm thử khả năng phục hồi:
  • AWS FIS (Fault Injection Service): chạy chaos experiment như terminate instance, tăng CPU, ngắt AZ, throttle API, dừng ECS task. Cấu hình stop condition bằng CloudWatch alarm để tự dừng khi ảnh hưởng quá lớn.
  • Resilience Hub: khai báo RTO/RPO mục tiêu (resiliency policy), đánh giá ứng dụng, gợi ý cải thiện, tích hợp vào pipeline.
  • Route 53 ARC: readiness check, routing control (bật/tắt traffic từng region bằng tay, độ tin cậy cao), zonal shift (chuyển traffic khỏi một AZ bị lỗi).

D4: Monitoring & Logging

CloudWatch
- Agent cần thiết để lấy memory, disk và log của OS. Cấu hình lưu trong Parameter Store, cài qua SSM.
- Metric filter: tạo metric từ log (không có dữ liệu cũ, chỉ tính từ khi tạo filter).
- Subscription filter: đẩy log real-time tới Kinesis Data Streams, Firehose, Lambda hoặc OpenSearch. Tối đa 2 filter mỗi log group.
- Gom log nhiều account: subscription → Logs destination (account đích) → Kinesis/Firehose.
- Gom log ra S3 gần real-time: subscription filter → Firehose → S3. Lệnh CreateExportTask không real-time (có thể mất tới 12 giờ).
- Metric streams: đẩy metric gần real-time tới Firehose → S3 hoặc công cụ bên thứ ba.
- Alarm nâng cao: anomaly detection alarm, composite alarm (giảm nhiễu), high-resolution metric (1 giây).
- Synthetics canary kiểm tra endpoint và UI định kỳ. Cross-account observability (account monitoring + source accounts).
- Retention: log group mặc định giữ vĩnh viễn, cần đặt retention. Mã hoá log group bằng KMS (key policy phải cho phép logs.<region>.amazonaws.com).

Phân tích log
- Athena truy vấn log trong S3 (CloudTrail, ALB, VPC Flow, S3 access log). Logs Insights truy vấn log trong CloudWatch.
- Quick Sight dùng làm dashboard business.

X-Ray / OpenTelemetry
- ⚠️ X-Ray SDK và daemon vào maintenance từ 25/02/2026, hết hỗ trợ 25/02/2027. AWS khuyến nghị OpenTelemetry (ADOT collector / ADOT Lambda layer / CloudWatch agent nhận OTLP). Dịch vụ X-Ray vẫn hoạt động bình thường (nhận trace OTLP, Transaction Search, Application Signals).
- Đề cũ vẫn hỏi theo X-Ray daemon: ECS chạy daemon sidecar (UDP 2000), EKS chạy DaemonSet, EC2 cài daemon. Đề mới: thay "daemon" bằng ADOT collector ở cùng vị trí.
- API Gateway: bật tracing ở stage. Lambda: bật Active tracing (role cần AWSXRayDaemonWriteAccess).
- Khái niệm: segment / subsegment, annotation (được index, lọc được) vs metadata (không index), sampling rule (reservoir + rate), group, service map.

Inspector: quét lỗ hổng cho EC2 (qua SSM Agent hoặc agentless), image trong ECR và Lambda. Bản hiện tại không còn "assessment template". Đề cũ có thể hỏi Inspector Classic: assessment target (nhóm EC2 theo tag) → assessment template (rules package: CVE, CIS Benchmarks, Network Reachability, Security Best Practices) → chạy cần Inspector agent; lên lịch bằng EventBridge.

Giám sát vận hành khác
- Trusted Advisor: kiểm tra chi phí, bảo mật, khả năng chịu lỗi, service limits. Kết quả gửi sang EventBridge để tự động xử lý (ví dụ thông báo key bị lộ, SG mở rộng). Gói Business/Enterprise Support mới có đủ các check.
- Service Quotas: xem quota, xin tăng quota, đặt CloudWatch alarm khi usage gần chạm quota. Có thể tạo quota request template cho account mới trong Organizations.
- DevOps Guru: ML phát hiện bất thường vận hành (latency, lỗi tăng) và gợi ý nguyên nhân, gần như không cần cấu hình.
- Compute Optimizer: gợi ý right-sizing cho EC2, ASG, EBS, Lambda, ECS trên Fargate.
- CloudWatch Logs Live Tail để xem log trực tiếp; Logs Insights để truy vấn trên nhiều log group.

D5: Incident & Event Response

  • EventBridge:
  • Nguồn event: AWS service, CloudTrail API call ("detail-type": "AWS API Call via CloudTrail"), AWS Health (aws.health), schedule.
  • Gửi event sang account khác bằng cross-account event bus. Archive và replay event.
  • AWS Health:
  • Event về sự cố dịch vụ, bảo trì theo lịch, EC2 retirement, và AWS_RISK_CREDENTIALS_EXPOSED (lộ access key).
  • Xử lý tự động bằng EventBridge → Lambda/Step Functions.
  • Xem toàn tổ chức bằng organizational view.
  • EC2 auto recovery: alarm StatusCheckFailed_System với action recover (hoặc simplified automatic recovery có sẵn).
  • Step Functions: workflow nhiều bước có retry, catch, chờ phê duyệt (callback task token).
  • Tự sửa trạng thái sai: Config rule + remediation; EventBridge + Lambda (ví dụ revert security group bị mở 0.0.0.0/0); SSM State Manager.

D6: Security & Compliance

  • Cách đánh giá quyền: explicit deny thắng. Quyền cuối cùng = giao giữa SCP/RCP, permission boundary, session policy và identity policy, cộng thêm resource policy khi truy cập cùng account.
  • Permission boundary: cho dev tự tạo role nhưng role đó không vượt quá boundary. Thêm điều kiện iam:PermissionsBoundary để ép buộc.
  • ABAC: aws:PrincipalTag so khớp với aws:ResourceTag. Dễ mở rộng khi có nhiều project.
  • Identity Center: permission set, nối với IdP bên ngoài (SAML/SCIM). Truy cập nhiều account không cần IAM user.
  • Credential cho máy: dùng IAM role. Secrets Manager rotation (managed rotation cho RDS, Lambda rotation cho loại khác). IAM Roles Anywhere cho máy on-prem.
  • Secrets Manager dùng cho DR: replicate secret sang region khác (replica secret). Chia sẻ cross-account: resource policy trên secret + customer managed KMS key (key aws/secretsmanager không dùng cross-account được).
  • Chặn ở quy mô tổ chức: S3 Block Public Access ở cấp account, SCP chặn tắt CloudTrail/GuardDuty/Config, SCP giới hạn region (aws:RequestedRegion), RCP đặt giới hạn tối đa cho resource (ví dụ chỉ principal trong tổ chức mới truy cập được bucket, dùng aws:PrincipalOrgID).
  • VPC endpoint policy: giới hạn endpoint chỉ truy cập bucket hoặc resource của tổ chức. Kết hợp với điều kiện aws:SourceVpce trong bucket policy.

Cheat sheet bổ sung (các vùng hay mất điểm)

1. Lambda deployment (D1 1.4)

  • Version bất biến, alias là con trỏ. Alias chia traffic: aws lambda update-alias --routing-config AdditionalVersionWeights={"2"=0.1}.
  • CodeDeploy config cho Lambda: CodeDeployDefault.LambdaCanary10Percent5Minutes / 10Minutes / 15Minutes / 30Minutes, LambdaLinear10PercentEvery1Minute / 2Minutes / 3Minutes / 10Minutes, LambdaAllAtOnce. Tự tạo config riêng được.
  • AppSpec Lambda: Resources (tên hàm, alias, CurrentVersion, TargetVersion) + Hooks: chỉ có BeforeAllowTraffic và AfterAllowTraffic. Hook phải gọi PutLifecycleEventHookExecutionStatus, nếu không thì chờ tới timeout 1 giờ.
  • SAM: AutoPublishAlias + DeploymentPreference (Type, Alarms, Hooks: PreTraffic/PostTraffic). Hàm hook nên đặt tên tiền tố CodeDeployHook_ (role CodeDeploy SAM tạo chỉ invoke được hàm có tiền tố này).
  • API Gateway: stage canary (canarySettings.percentTraffic) và stage variables trỏ tới alias.
  • Scale: reserved concurrency (giới hạn + đảm bảo), provisioned concurrency (khử cold start, scale theo lịch bằng Application Auto Scaling).

3. AWS AppConfig (D2 2.1)

  • Application → environment → configuration profile (freeform: YAML/JSON/text từ AppConfig hosted, S3, Parameter Store, Secrets Manager...; hoặc feature flag) → deployment strategy → deployment.
  • Khác Parameter Store: triển khai dần (linear/exponential), bake time, validator (JSON Schema hoặc Lambda) chặn cấu hình sai, rollback tự động theo CloudWatch alarm.
  • Strategy có sẵn: AppConfig.AllAtOnce, AppConfig.Linear50PercentEvery30Seconds (test), AppConfig.Linear20PercentEvery6Minutes, AppConfig.Canary10Percent20Minutes (khuyến nghị production).
  • Ứng dụng đọc qua StartConfigurationSession + GetLatestConfiguration; Lambda dùng AppConfig Lambda extension (cache ở localhost:2772).
  • Từ khoá đề: "feature flag", "bật tính năng dần cho người dùng", "cấu hình sai phải tự rollback" → AppConfig.

4. CodeCommit (D1 1.1)

  • Trạng thái: ngừng nhận khách mới 25/07/2024, trở lại GA cho khách mới từ 24/11/2025. Đề vẫn hỏi nhiều.
  • Chặn push/merge trực tiếp vào main: IAM policy Deny codecommit:GitPush, MergeBranchesBy*, PutFile... với condition StringEqualsIfExists codecommit:References = refs/heads/main + Null codecommit:References = false.
  • Approval rule template gắn vào repo: PR cần N người duyệt (theo pool ARN) trước khi merge.
  • Notification rule (SNS/Chatbot) và trigger (SNS/Lambda khi push). Sự kiện repo/PR có trong EventBridge → kích hoạt CodeBuild chạy test trên PR.
  • Cross-account: role trong account chứa repo + git-remote-codecommit dùng profile assume role. Mã hoá bằng KMS (AWS managed hoặc customer managed key).
  • Review code tự động trên PR: đề cũ chọn CodeGuru Reviewer (đã ngừng nhận repo mới từ 11/2025, chuyển sang Amazon Q Developer/CodeGuru Security). Nếu đề chỉ có CodeGuru Reviewer thì chọn nó.

6. Storage pattern khi deploy (D1 1.4, D3)

  • EFS: chia sẻ giữa nhiều instance/AZ, mount được cho EC2, ECS (Fargate cả), EKS, Lambda. Có lifecycle (IA), replication sang region khác, backup bằng AWS Backup. Dùng cho dữ liệu dùng chung của app stateful khi instance bị thay (immutable).
  • EBS: gắn 1 AZ, snapshot (DLM / AWS Backup), Multi-Attach chỉ io1/io2 cùng AZ. Instance bị thay thì dữ liệu EBS gốc mất (trừ khi tách volume).
  • S3: artifact, static asset, log. Instance store: tạm thời, mất khi stop.
  • FSx: Windows File Server (SMB, AD), Lustre (HPC, liên kết S3), NetApp ONTAP (đa giao thức, multi-AZ), OpenZFS (NFS hiệu năng cao).
  • Đề: "app trên ASG cần thư mục upload dùng chung, instance có thể bị thay bất kỳ lúc nào" → EFS.

7. Chọn scaling policy (D3 3.2)

  • Target tracking: mặc định, giữ metric quanh mục tiêu (CPU 50%, ALBRequestCountPerTarget). Ít cấu hình nhất.
  • Step scaling: nhiều bậc theo mức vượt ngưỡng alarm, dùng metric custom, phản ứng mạnh hơn khi vượt xa.
  • Simple scaling: cũ, phải chờ cooldown.
  • Scheduled: tải biết trước (9h sáng thứ Hai).
  • Predictive: tải có chu kỳ lặp lại, dùng ML dự báo và scale trước. Chạy chế độ forecast only trước khi bật forecast and scale.
  • Default instance warm-up (khuyến nghị bật) vs cooldown (simple scaling). Scale-in protection cho instance đang xử lý job dài.
  • Queue: scale theo backlog per instance (ApproximateNumberOfMessagesVisible / số instance) bằng target tracking với metric math.
  • Khác: ECS capacity provider managed scaling (ASG theo task), Service Auto Scaling (số task), DynamoDB auto scaling hoặc on-demand, RDS storage auto scaling, Aurora Auto Scaling (replica), Lambda concurrency, API Gateway throttling (bảo vệ backend).

9. Caching và điểm vào toàn cầu (D3)

  • ElastiCache Redis OSS/Valkey: Multi-AZ auto-failover, cluster mode (sharding), Global Datastore cross-Region, backup. Memcached: đơn giản, không replication. DAX cho DynamoDB (microsecond).
  • CloudFront + origin group (failover khi primary trả lỗi cấu hình được như 500/502/503/504/403/404).
  • Global Accelerator: 2 static anycast IP, đi backbone AWS, health check + failover vài giây (không phụ thuộc DNS TTL), traffic dial theo region, hỗ trợ TCP/UDP. Chọn khi đề nói "IP cố định để whitelist", "UDP/gaming", "failover không bị cache DNS". Route 53 chọn khi đề nói DNS routing (latency, geolocation, weighted).

10. CloudFormation nâng cao bổ sung (D2 2.1)

  • Nested stack (AWS::CloudFormation::Stack): tái sử dụng template trong cùng vòng đời. Cross-stack (Outputs.Export + Fn::ImportValue): chia sẻ giữa stack độc lập; stack đang bị import không xoá/sửa được export đó.
  • Registry: resource type public (bên thứ ba) và private (tự viết), module (cfn init → cfn submit, dùng như resource Org::Team::Name::MODULE), Hooks.
  • Macro: transform có sẵn AWS::Serverless-2016-10-31 (SAM), AWS::Include, AWS::LanguageExtensions (Fn::ForEach, Fn::Length); macro tự viết bằng Lambda.
  • Parameters (kiểu AWS::SSM::Parameter::Value<String> lấy AMI mới nhất), Mappings (AMI theo region), Conditions (IsProd).
  • DeletionPolicy mặc định là Delete; riêng RDS/Neptune cluster không khai báo thì là Snapshot; có thêm RetainExceptOnCreate.

11. Event-driven pattern (D5 5.1)

  • SNS fan-out → nhiều SQS (mỗi consumer một queue), filter policy trên subscription (lọc theo attribute hoặc body).
  • SQS: visibility timeout ≥ 6 lần timeout của Lambda consumer, DLQ + maxReceiveCount, redrive về queue gốc, FIFO (message group ID, dedup 5 phút).
  • Lambda event source mapping: batch size/window, ReportBatchItemFailures, với Kinesis/DynamoDB Streams có BisectBatchOnFunctionError, MaximumRetryAttempts, MaximumRecordAgeInSeconds, on-failure destination. Async invoke có destinations (OnSuccess/OnFailure) và DLQ.
  • Kinesis Data Streams: shard (1 MB/s ghi, 2 MB/s đọc), enhanced fan-out (mỗi consumer 2 MB/s riêng), on-demand mode, metric IteratorAge tăng = consumer chậm. Firehose: nạp gần real-time (buffer) vào S3/OpenSearch/Redshift/Splunk, không có consumer tự viết.
  • EventBridge Pipes: nối source (SQS, Kinesis, DynamoDB Streams) → filter → enrich → target, không cần Lambda keo dán.

12. Security network (D6 6.2)

  • SG: stateful, chỉ allow, gắn ENI. NACL: stateless, có deny, theo thứ tự số rule, gắn subnet, phải mở ephemeral port (1024–65535) cho chiều về. Chặn 1 IP cụ thể → NACL deny (SG không deny được).
  • WAF: Web ACL gắn ALB, API Gateway REST, CloudFront, AppSync, Cognito user pool, App Runner, Verified Access. Managed rule group (Core rule set, SQLi, Known bad inputs, IP reputation, Bot Control), rate-based rule, geo match, IP set. Log tới S3/CloudWatch Logs/Firehose (tên bắt đầu aws-waf-logs-).
  • Shield Standard miễn phí tự động. Shield Advanced ($3.000/tháng/org, cam kết 1 năm): Shield Response Team, cost protection khi bị DDoS scale, WAF miễn phí cho tài nguyên được bảo vệ, health-based detection.
  • Network Firewall: firewall managed trong VPC (stateless + stateful rule group, Suricata, domain list), cần subnet riêng và sửa route table. Firewall Manager: áp WAF/Shield/SG/Network Firewall/DNS Firewall policy cho cả Organizations, cần AWS Config bật và account admin.

13. ACM / PKI (D6 6.2)

  • Public cert miễn phí, xác thực DNS (tự gia hạn khi CNAME còn) hoặc email (phải bấm lại). Cert import không tự gia hạn → dùng EventBridge sự kiện ACM Certificate Approaching Expiration (mặc định 45 ngày trước) + Config rule acm-certificate-expiration-check.
  • Cert cho CloudFront phải ở us-east-1. ALB/API Gateway regional dùng cert cùng region. ACM cert gắn ELB/CloudFront không export private key (trừ loại exportable public cert có phí ra mắt 2025).
  • AWS Private CA: CA nội bộ (root/subordinate), cấp cert private cho mTLS, IoT, IAM Roles Anywhere; có chế độ short-lived cert rẻ hơn.

14. KMS gom lại (D6 6.2)

  • Quyền = key policy (bắt buộc, phải cho phép account root nếu muốn IAM policy có tác dụng) + IAM policy + grant (cấp tạm, dùng bởi dịch vụ như EBS/RDS).
  • Key AWS managed (aws/s3, aws/ebs...) không sửa được key policy, không dùng cross-account. Cross-account cần customer managed key.
  • Automatic rotation: bật được cho symmetric CMK, chu kỳ 90–2560 ngày (mặc định 365), key ID không đổi. Có thêm on-demand rotation.
  • Multi-Region key: cùng key ID ở nhiều region, giải mã cross-Region không cần gọi lại region gốc (DR, Global Tables client-side).
  • Dịch vụ dùng KMS cần service principal trong key policy: CloudWatch Logs (logs.<region>.amazonaws.com), CloudTrail, SNS/SQS khi nhận từ dịch vụ khác (EventBridge, S3 event) phải cho principal dịch vụ đó kms:GenerateDataKey* + kms:Decrypt.
  • S3 SSE-KMS cross-account: bucket policy + key policy đều phải cho phép. EBS snapshot mã hoá chia sẻ: share snapshot + share key (hoặc re-encrypt bằng key bên nhận).

15. IAM bổ sung (D6 6.1)

  • aws:MultiFactorAuthPresent, aws:MultiFactorAuthAge (ép MFA); CLI dùng sts get-session-token --serial-number --token-code.
  • Session policy truyền khi AssumeRole: thu hẹp quyền của phiên. Session tags + sts:TagSession cho ABAC; sts:SourceIdentity để truy vết người thật qua chuỗi role.
  • iam:PassRole + condition iam:PassedToService (chỉ cho truyền role vào dịch vụ cụ thể).
  • OIDC federation cho CI bên ngoài (GitHub Actions, GitLab): tạo IAM OIDC identity provider + role trust với token.actions.githubusercontent.com:sub → không cần access key lâu dài.
  • Cognito: user pool (đăng nhập ứng dụng, JWT) + identity pool (đổi token lấy AWS credential tạm).

16. CloudTrail (D4, D6 6.3)

  • Management events (mặc định, bản đầu tiên miễn phí) vs data events (S3 object, Lambda invoke, DynamoDB item; tính phí, phải bật riêng, nên dùng advanced event selector để lọc) vs Insights events (phát hiện lượng API bất thường).
  • Organization trail: member account thấy nhưng không sửa/xoá được. Log file integrity validation (digest SHA-256 + RSA). CloudTrail Lake: lưu và truy vấn SQL, giữ tới 10 năm (tuỳ gói).
  • VPC Flow Logs: ghi IP/port/accept-reject, không ghi nội dung gói; đưa ra S3 (parquet, partition theo giờ để Athena rẻ) hoặc CloudWatch Logs.

17. Giám sát vận hành khác (D4, D5)

  • Amazon Managed Service for Prometheus (lưu và truy vấn PromQL metric container/EKS) + Amazon Managed Grafana (dashboard, SSO qua Identity Center). Đề hỏi "giám sát EKS bằng Prometheus mà không tự vận hành server" → 2 dịch vụ này.
  • Trusted Advisor check → EventBridge (thông báo/tự sửa); tổ chức xem bằng organizational view. Service Quotas + alarm usage.
  • OpsCenter: OpsItem tự tạo từ EventBridge rule hoặc CloudWatch alarm, gắn runbook Automation để xử lý.
  • EC2 auto recovery: alarm StatusCheckFailed_System + action recover; giữ instance ID, private IP, EIP, metadata. Chỉ áp dụng instance dùng EBS, không có instance store. Nhiều loại instance có simplified automatic recovery bật sẵn. StatusCheckFailed_Instance (lỗi OS) → action reboot, không phải recover.

Mẹo làm bài Professional

  • Đọc câu hỏi (dòng cuối) trước, sau đó mới đọc tình huống, tìm các ràng buộc như "least operational overhead", "most cost-effective", "minimize downtime", "across all accounts".
  • Thường có 2 đáp án đều chạy được. Chọn đáp án managed, tự động, mở rộng được cho nhiều account (Organizations, StackSets, Config + remediation, delegated admin). Đáp án dùng script tự viết hoặc làm tay thường sai.
  • Từ khoá trong đề gợi ý đáp án:
  • "all accounts, including new ones": dùng StackSets service-managed (auto-deploy) hoặc Control Tower.
  • "near real-time logs": dùng subscription filter, không dùng export task.
  • "RPO seconds": dùng Aurora Global hoặc DynamoDB Global Tables.
  • "remediate automatically": dùng Config + SSM Automation hoặc EventBridge + Lambda.
  • Quản lý thời gian: sau 60 phút nên làm xong khoảng 25 câu. Câu nào quá 4 phút thì flag lại và làm tiếp.
