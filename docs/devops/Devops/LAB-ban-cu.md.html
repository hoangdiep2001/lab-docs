Tự làm thêm:
- Cố ý làm 1 test fail: build FAILED vì pytest trả exit code ≠ 0.
- Đổi computeType sang Lambda compute (BUILD_LAMBDA_1GB) cho build nhẹ, so sánh thời gian khởi động.
- Bật batch build (batch: build-matrix) để test trên nhiều runtime song song.

Ghi nhớ cho đề thi:
- Build Docker trong CodeBuild: privilegedMode = true (trừ khi dùng image Docker-in-Docker riêng). Quên bật → lỗi Cannot connect to the Docker daemon.
- Test report (JUnit, NUnit, TestNG, Cucumber, Visual Studio TRX) và coverage (Clover, Cobertura, JaCoCo, SimpleCov) nằm ở khối reports, xem tập trung trên console, có thể tạo alarm theo report.
- Build trên PR: webhook filter group (EVENT, BASE_REF, HEAD_REF, FILE_PATH, ACTOR_ACCOUNT_ID). Muốn chặn merge khi build fail: dùng branch protection của GitHub với commit status từ CodeBuild.
- CodeArtifact: muốn proxy và cache package công khai → external connection (mỗi repo chỉ 1 external connection). Chia sẻ cho nhiều account → domain policy + repository policy. Pipeline bị chặn internet → CodeArtifact + VPC endpoint codeartifact.api + codeartifact.repositories.
- Biến truyền giữa các action trong pipeline: exported-variables (CodeBuild) + namespace của action trong CodePipeline (#{BuildVariables.IMAGE_TAG}).

  1. Deploy bản tốt → CodeDeploy copy ASG thành ASG mới (green), cài app, chuyển ALB sang, giữ blue 30 phút.
  2. Sửa validate.sh thành exit 1 → deploy → hook ValidateService fail → tự rollback.
  3. SSH vào bằng Session Manager, xem /var/log/aws/codedeploy-agent/codedeploy-agent.log và /opt/codedeploy-agent/deployment-root/.

Tự làm thêm:
- Scale ASG từ 2 lên 3 khi không có deployment nào: instance mới tự nhận revision gần nhất (CodeDeploy gắn lifecycle hook vào ASG).
- Tạo trigger SNS hoặc EventBridge rule aws.codedeploy → CodeDeploy Deployment State-change Notification.

Ghi nhớ cho đề thi:
- Thứ tự hooks EC2 có ALB: BeforeBlockTraffic → BlockTraffic → AfterBlockTraffic → ApplicationStop → DownloadBundle → BeforeInstall → Install → AfterInstall → ApplicationStart → ValidateService → BeforeAllowTraffic → AllowTraffic → AfterAllowTraffic. Các hook *Block*/*Allow*Traffic, DownloadBundle, Install không chạy script được.
- ApplicationStop chạy script của revision cũ. Script cũ lỗi chặn mọi deployment → --ignore-application-stop-failures (hoặc xoá thư mục deployment-root cũ).
- Rollback = deployment mới dùng revision tốt gần nhất (có deployment ID mới). Không có revision tốt nào trước đó thì không rollback được.
- ASG scale-out trong lúc đang deploy → instance mới có thể nhận revision cũ. AWS khuyên tạm suspend scale-out hoặc deploy lại sau. CodeDeploy tự thêm lifecycle hook CodeDeploy-managed-automatic-launch-deployment-hook.
- Deployment config tuỳ chỉnh: --minimum-healthy-hosts type=FLEET_PERCENT,value=75. HalfAtATime, OneAtATime chỉ dùng cho EC2/on-prem. Lambda/ECS dùng Canary/Linear/AllAtOnce.
- On-premises: đăng ký bằng IAM user (register-on-premises-instance) hoặc IAM session ARN; khuyến nghị dùng SSM hybrid activation để quản lý agent.

3d. Pipeline V2: trigger theo tag + condition

8e. Aurora Global Database (chỉ lý thuyết, cluster tốn phí)

Ghi nhớ cho đề thi:
- Chọn chiến lược DR từ RTO/RPO + chi phí: Backup & Restore (giờ) → Pilot Light (chục phút, chỉ dữ liệu chạy) → Warm Standby (phút, bản thu nhỏ chạy sẵn) → Active/Active (gần 0).

Lab 13: Troubleshooting drills (D1–D6)

Cách luyện: đọc triệu chứng, tự trả lời "xem ở đâu" và "sửa thế nào" trước khi mở đáp án. Nếu còn thời gian, dựng lại lỗi bằng tài nguyên của các lab trước.

Drill 1: CodeDeploy deployment đứng ở Pending rồi fail "The overall deployment failed because too many individual instances failed"; instance có log rỗng. - **Xem:** `sudo systemctl status codedeploy-agent`; `/var/log/aws/codedeploy-agent/codedeploy-agent.log`; instance profile. - **Nguyên nhân:** agent không cài/không chạy, hoặc instance profile không có quyền S3 đọc revision, hoặc không ra internet/thiếu VPC endpoint `codedeploy` + `codedeploy-commands-secure` + S3. - **Sửa:** cài agent bằng **SSM Distributor** (`AWSCodeDeployAgent`) + State Manager để luôn giữ agent; gắn đủ quyền; thêm endpoint.
Drill 2: Stack có ASG + CreationPolicy báo CREATE_FAILED sau đúng 10 phút (bằng Timeout: PT10M trong template Lab 4a): "Failed to receive 2 resource signal(s) within the specified duration". - **Xem:** `/var/log/cfn-init.log`, `/var/log/cloud-init-output.log` trên instance (Session Manager / EC2 serial console). Tạm tắt rollback (`--disable-rollback` hoặc *Preserve successfully provisioned resources*) để còn instance mà xem. - **Nguyên nhân:** cfn-init lỗi (package sai), không gọi cfn-signal, sai logical ID trong `-r`, subnet private không NAT/endpoint nên không gọi được endpoint CloudFormation. - **Sửa:** sửa script, `cfn-signal -e $?` sau `cfn-init`, đảm bảo đường mạng, tăng `Timeout` nếu app khởi động lâu.
Drill 3: Stack kẹt ở UPDATE_ROLLBACK_FAILED vì ai đó đã xoá tay một resource. - **Sửa:** `aws cloudformation continue-update-rollback --stack-name X --resources-to-skip ` (hoặc tạo lại resource thủ công cho khớp). Sau đó update lại stack. - **Phòng ngừa:** stack policy, IAM/SCP chặn sửa tay resource có tag `aws:cloudformation:stack-name`, drift detection định kỳ.
Drill 4: ECS task STOPPED với CannotPullContainerError ... i/o timeout (Fargate, subnet private). - **Xem:** `aws ecs describe-tasks --query 'tasks[].stoppedReason'`. - **Nguyên nhân:** không có đường tới ECR: thiếu NAT, hoặc thiếu VPC endpoint `ecr.api`, `ecr.dkr` **và gateway endpoint S3** (layer nằm trên S3) + `logs`. Nếu lỗi là `AccessDenied` → **task execution role** thiếu `ecr:GetAuthorizationToken`/`BatchGetImage`. Image ở account khác → repository policy cho account đó. - **Sửa:** thêm endpoint/NAT; sửa execution role (không phải task role).
Drill 5: ASG liên tục terminate và launch instance mới ("unhealthy loop") ngay sau mỗi lần deploy. - **Xem:** Activity history của ASG ("ELB health check failed"), target group health reason, app log. - **Nguyên nhân:** health check grace period quá ngắn so với thời gian app khởi động; health check path trả 3xx/4xx; SG của instance không cho ALB truy cập port health check. - **Sửa:** tăng grace period/dùng lifecycle hook chờ app sẵn sàng; sửa path/matcher; tạm **suspend `ReplaceUnhealthy`** để debug.
Drill 6: Pipeline cross-account: action CloudFormation ở account đích fail AccessDenied / "Error calling GetObject" / KMS.AccessDeniedException. - **Kiểm tra theo thứ tự:** artifact bucket dùng **CMK** (không phải `aws/s3`) → key policy có account đích → bucket policy có account đích → role ở account đích có quyền `kms:Decrypt` + `s3:GetObject` trên tài nguyên của account công cụ → trust policy của role cho account công cụ → pipeline role có `sts:AssumeRole` vào role đích.
Drill 7: EC2 mới không xuất hiện trong Systems Manager Fleet Manager, Patch Manager bỏ qua máy đó. - **Nguyên nhân & sửa:** agent không chạy (`systemctl status amazon-ssm-agent`); thiếu instance profile `AmazonSSMManagedInstanceCore` (hoặc bật **Default Host Management Configuration**); subnet private thiếu endpoint `ssm`, `ssmmessages`, `ec2messages`; giờ hệ thống lệch; máy không có tag `Patch Group` đúng.
Drill 8: Tạo subscription filter từ log group của account PROD tới destination ở account TOOLS báo "AccessDeniedException ... not authorized to perform logs:PutSubscriptionFilter". - **Nguyên nhân:** **destination policy** chưa cho account PROD (hoặc OrgID); role mà destination dùng (trust `logs.amazonaws.com`) thiếu quyền ghi Kinesis/Firehose; destination ở region khác log group. - **Sửa:** `put-destination-policy` với principal là account PROD hoặc điều kiện `aws:PrincipalOrgID`; kiểm tra role.
Drill 9: Một số stack instance của StackSet ở trạng thái OUTDATED sau khi update. - **Xem:** `aws cloudformation list-stack-instances --stack-set-name X` cột `StatusReason`; vào account đó xem events của stack. - **Nguyên nhân:** resource trùng tên đã tồn tại, thiếu quota, SCP chặn hành động/region, self-managed thiếu `AWSCloudFormationStackSetExecutionRole` hoặc trust sai, vượt `FailureTolerance`. - **Sửa:** sửa nguyên nhân rồi chạy `update-stack-instances` cho account/region đó (hoặc tăng failure tolerance nếu chấp nhận).
Drill 10: Config rule hiện NON_COMPLIANT, remediation auto bật nhưng trạng thái "Action execution failed". - **Xem:** Systems Manager → Automation → execution lỗi → step lỗi. - **Nguyên nhân:** `AutomationAssumeRole` thiếu quyền hoặc trust không phải `ssm.amazonaws.com`; tham số truyền sai (`RESOURCE_ID` vs ARN); hết `MaximumAutomaticAttempts`. - **Sửa:** sửa role/tham số, chạy lại remediation thủ công để kiểm chứng.
Drill 11: Lambda deploy bằng CodeDeploy canary bị rollback dù code không lỗi; hook BeforeAllowTraffic timeout. - **Nguyên nhân:** hàm hook không gọi `codedeploy:PutLifecycleEventHookExecutionStatus` (thiếu quyền hoặc quên gọi) → CodeDeploy chờ tới timeout (1 giờ) rồi fail.
