Điểm mới của C03 (phải học)

  • OCSF và Security Lake: chuẩn hoá log, tích hợp với SIEM bên thứ ba. Có thêm WAF rule của bên thứ ba.
  • Bảo mật GenAI: OWASP Top 10 cho LLM, Bedrock Guardrails.
  • Mã hoá giữa các node (inter-node encryption) cho EMR, EKS, SageMaker; mã hoá sẵn ở tầng Nitro.
  • Imported key material: khác gì key do AWS sinh ra; external key store (XKS).
  • Che dữ liệu nhạy cảm (masking): CloudWatch Logs data protection, SNS message data protection.
  • KMS multi-Region key và Private CA.
  • Validate finding để đánh giá phạm vi và mức độ ảnh hưởng của sự cố.
  • Phần quản trị có thêm: RCP, declarative policy, AI opt-out policy, quản lý root tập trung (centralized root access), quy trình break-glass.
  • Đã bỏ: ASFF, kiến thức nền TCP/IP và OSI, các thành phần của policy, khái niệm TLS cơ bản, S3 static website, host-based firewall.

Ngoài phạm vi thi

Thiết kế thuật toán mã hoá, phân tích gói tin (packet), kiến trúc tổng thể, quản lý máy người dùng cuối, train model ML.

Cheat sheet (high-yield)

D4: IAM

Cách đánh giá policy:
1. Có explicit Deny ở bất kỳ policy nào thì DENY.
2. SCP, RCP (trong Organizations) phải cho phép.
3. Có resource policy cho phép (cùng account): ALLOW, trừ khi bị chặn ở các bước trên.
- ⚠️ Chỉ đúng khi resource policy ghi đích danh ARN của IAM user hoặc role. Nếu resource policy ghi arn:aws:iam::<acct>:root (cả account) thì vẫn cần identity policy cho phép.
- Khi resource policy ghi đích danh ARN của IAM user, permission boundary không giới hạn quyền đó.
- Khi resource policy ghi ARN của role, quyền đó vẫn bị permission boundary và session policy giới hạn (implicit deny của chúng có hiệu lực). Nếu ghi ARN của role session (arn:aws:sts::<acct>:assumed-role/<role>/<session>) thì quyền cấp thẳng cho session, boundary và session policy không giới hạn. Đề rất hay gài chỗ này.
4. Identity policy phải cho phép, đồng thời nằm trong giới hạn của permission boundary và session policy.
5. Nếu không có gì cho phép thì mặc định DENY.

Cross-account: cần cả identity policy ở account nguồn lẫn resource policy hoặc trust policy ở account đích cho phép.

Trường hợp đặc biệt của KMS: key policy là bắt buộc. Nếu key policy không có statement cho account root (arn:aws:iam::<acct>:root), thì IAM policy không có tác dụng với key đó.

Cần Dùng

Presigned URL (S3):
- Quyền là của người ký: người ký mất quyền thì URL cũng hết dùng được.
- Hết hạn = min(--expires-in, thời hạn credential của người ký). Ký bằng IAM user (SigV4) tối đa 7 ngày; ký bằng role thì URL chết khi session của role hết hạn (thường ≤ 1–12 giờ). Ký trong console tối đa 12 giờ.
- Chặn dùng presigned URL từ ngoài mạng công ty: bucket policy Deny với aws:SourceIp / aws:SourceVpce, hoặc giới hạn tuổi chữ ký bằng s3:signatureAge.

Condition key và khái niệm hay ra:

Key / khái niệm Dùng để
aws:PrincipalOrgID / aws:PrincipalOrgPaths Chỉ cho principal thuộc tổ chức / thuộc một OU cụ thể
aws:ResourceOrgID / aws:ResourceAccount Chỉ cho principal của mình truy cập resource của tổ chức mình (chặn đẩy dữ liệu sang bucket ngoài)
aws:CalledVia / aws:ViaAWSService Cho phép khi request do service gọi thay (ví dụ Athena gọi S3, CloudFormation tạo resource)

Data perimeter 3 lớp: identity (SCP + aws:ResourceOrgID), resource (RCP/bucket policy + aws:PrincipalOrgID), network (VPC endpoint policy + aws:SourceVpce/aws:SourceIp)

Cognito (bổ sung): managed login/hosted UI, Lambda trigger (pre sign-up, pre token generation để thêm claim), token revocation (thu hồi refresh token), app client secret cho backend, identity pool có thể cho unauthenticated identity (phải hạn chế quyền), threat protection (gói Plus) chặn đăng nhập rủi ro và mật khẩu bị lộ.

D5: Data Protection

KMS
- Phân loại key:
- AWS owned: không thấy, không quản lý được.
- AWS managed (aws/s3): không sửa được key policy, không chia sẻ cross-account được.
- Customer managed: toàn quyền kiểm soát. Bắt buộc dùng loại này khi cần chia sẻ cross-account, ví dụ chia sẻ snapshot EBS/RDS đã mã hoá.
- Rotation: key symmetric do AWS sinh có thể bật tự động (mặc định 365 ngày, chọn được 90–2560 ngày) hoặc xoay on-demand. Key ID không đổi, các bản cũ vẫn được giữ để giải mã dữ liệu cũ. Key asymmetric, HMAC, key trong custom key store không xoay tự động được.
- Imported key material (BYOK):
- Bạn tự sinh key material, bọc (wrap) bằng public key mà KMS cung cấp, rồi import vào.
- Có thể đặt ngày hết hạn, và xoá key material ngay lập tức (không phải đợi 7–30 ngày).
- Bạn chịu trách nhiệm về độ bền: phải tự giữ bản gốc, AWS không khôi phục được.
- Không có automatic rotation, nhưng từ 06/2025 có on-demand rotation cho key symmetric có imported material (kể cả multi-Region key): import key material mới với --import-type NEW_KEY_MATERIAL (material ở trạng thái PENDING_ROTATION), rồi gọi rotate-key-on-demand. Một key có thể gắn nhiều key material; tất cả phải còn được import thì key mới dùng được. Cách cũ (tạo key mới + trỏ alias) vẫn đúng nếu đề không nhắc on-demand.
- Hỗ trợ key symmetric, asymmetric, HMAC và multi-Region key; không dùng được với key trong custom key store. Key asymmetric/HMAC chỉ gắn được đúng một key material.
- Reimport (mặc định EXISTING_KEY_MATERIAL) phải dùng đúng material đã gắn với key; mỗi lần import phải lấy wrapping key + import token mới. Hết hạn tối đa 365 ngày; hết hạn hoặc bị xoá thì key chuyển PendingImport.
- Custom key store:
- CloudHSM key store: key nằm trong cluster CloudHSM của bạn.
- External key store (XKS): key nằm ngoài AWS (HSM on-prem). Bạn chịu trách nhiệm về độ trễ và tính sẵn sàng; nếu ngắt kết nối thì AWS không giải mã được (giống một "kill switch").
- Multi-Region key: các key ở nhiều region có cùng key ID và key material, mã hoá ở region này rồi giải mã ở region khác. Mỗi region có key policy riêng. Không phải key global: phải replicate chủ động.
- Encryption context: dữ liệu xác thực bổ sung (AAD), được ghi vào CloudTrail. Dùng trong điều kiện kms:EncryptionContext:. Grants cấp quyền tạm thời, có thể ủy quyền tiếp (EBS, RDS dùng cơ chế này). kms:ViaService giới hạn chỉ cho dùng key qua một service nhất định.
- Xoá key: chờ 7–30 ngày. Nếu chưa chắc thì Disable trước. Phát hiện việc dùng key trong thời gian chờ xoá bằng CloudTrail + EventBridge/alarm.

Các dịch vụ khác
- CloudHSM: single-tenant, FIPS 140-3 Level 3, khách hàng tự quản lý user và key, AWS không có quyền truy cập. Dùng cho SSL offload, Oracle TDE, PKCS#11/JCE/CNG. Để HA cần ≥ 2 HSM ở các AZ khác nhau.
- ACM:
- Certificate public miễn phí, tự gia hạn (nên validate bằng DNS). Certificate import vào không tự gia hạn; dùng EventBridge hoặc Config rule acm-certificate-expiration-check để cảnh báo.
- Certificate gắn với region. CloudFront cần certificate ở us-east-1.
- Từ 06/2025 có exportable public certificate (phải chọn khi request, có phí): xuất được cả private key để dùng ngoài AWS (EC2 tự quản, on-prem). Certificate thường của ACM vẫn không export được private key.
- Private CA: cấp certificate nội bộ (mTLS, Roles Anywhere, IoT). Có chế độ general-purpose và short-lived (rẻ hơn). Dùng cross-account qua RAM.
- Secrets Manager: rotation qua Lambda hoặc managed rotation, replicate secret sang region khác, resource policy cho cross-account (secret phải mã hoá bằng CMK). Parameter Store SecureString không tự rotate được.

Data in transit
- ELB: security policy (ví dụ ELBSecurityPolicy-TLS13-1-2-2021-06) để chặn TLS cũ. ALB/NLB terminate TLS. Dùng NLB TCP passthrough nếu cần TLS end-to-end tới backend.
- CloudFront: viewer protocol policy = Redirect HTTP to HTTPS, origin protocol policy = HTTPS only. Dùng field-level encryption cho dữ liệu nhạy cảm.
- Bắt buộc dùng TLS khi gọi S3 hoặc các service khác: thêm Deny với điều kiện "aws:SecureTransport": "false". Có thể chặn TLS cũ bằng s3:TlsVersion. RDS: rds.force_ssl=1.
- Nitro: một số loại instance tự mã hoá traffic giữa các instance cùng loại trong VPC. EMR: security configuration in-transit. EKS: service mesh/mTLS, hoặc Nitro. SageMaker: inter-container traffic encryption.
- Kết nối riêng tư:
- Gateway endpoint: chỉ có cho S3 và DynamoDB, miễn phí, cấu hình qua route table.
- Interface endpoint (PrivateLink): dùng ENI, có SG, tính phí.
- Endpoint policy + điều kiện aws:SourceVpce trong bucket policy.
- Hybrid:
- Direct Connect không mã hoá. Cần mã hoá thì dùng MACsec (tầng 2, chỉ có trên dedicated connection 10/100/400 Gbps và LAG tại một số PoP; không có trên hosted connection; không tốn thêm phí) hoặc Site-to-Site VPN over DX (IPsec, dùng được cả với hosted connection).
- Client VPN dùng cho người dùng.
- Verified Access: truy cập ứng dụng nội bộ theo mô hình zero-trust, không cần VPN.

Envelope encryption: KMS chỉ mã hoá trực tiếp tối đa 4 KB. Dữ liệu lớn: GenerateDataKey → dùng data key plaintext mã hoá dữ liệu cục bộ (AES-GCM) → xoá plaintext khỏi bộ nhớ → lưu data key đã mã hoá cạnh dữ liệu. Giải mã: Decrypt data key rồi giải mã dữ liệu. AWS Encryption SDK làm sẵn việc này (có data key caching để giảm số lần gọi KMS và tránh throttling). Data at rest ngoài S3
- EBS encryption by default: bật theo từng region (enable-ebs-encryption-by-default), có thể chọn CMK mặc định; ép cả tổ chức bằng declarative policy hoặc SCP ec2:Encrypted. Không mã hoá được volume đang có tại chỗ: snapshot → copy-snapshot --encrypted → tạo volume mới.
- RDS: chỉ bật mã hoá lúc tạo. Instance chưa mã hoá: snapshot → copy snapshot có KMS key → restore thành instance mới. Read replica phải cùng trạng thái mã hoá với primary.
- DynamoDB: luôn mã hoá at rest, chọn 1 trong 3: AWS owned key (mặc định, miễn phí), AWS managed key (aws/dynamodb), customer managed key (audit được trong CloudTrail, chia sẻ/thu hồi được).
- S3 Bucket Key: giảm tới 99% số lần gọi KMS cho SSE-KMS (key cấp bucket sinh data key cho nhiều object). Encryption context trong CloudTrail lúc này là ARN của bucket thay vì object.
- EFS: mã hoá at rest chọn lúc tạo; lifecycle policy chuyển file ít dùng sang IA/Archive. FSx for Lustre: backup (file system persistent) và mã hoá in-transit trên instance hỗ trợ. DataSync: truyền dữ liệu bằng TLS, có kiểm tra toàn vẹn (checksum).
- Nitro Enclaves: môi trường cô lập trong EC2 (không có ổ đĩa, không mạng, không SSH); KMS key policy dùng điều kiện kms:RecipientAttestation:ImageSha384 để chỉ enclave đúng image mới giải mã được.

Private CA (bổ sung): cấu trúc phân cấp root CA → subordinate CA (root thường để offline/ít dùng); template quyết định loại certificate (EndEntityClientAuthCertificate, CodeSigningCertificate, SubordinateCACertificate_PathLen0...); thu hồi qua CRL (lưu S3) hoặc OCSP; chế độ short-lived (certificate ≤ 7 ngày, rẻ hơn, không cần thu hồi). Chia sẻ CA cross-account bằng RAM.

Masking: CloudWatch Logs data protection policy (audit và mask, cần quyền logs:Unmask để xem bản gốc), SNS message data protection (audit, de-identify, deny), Macie (tìm PII trong S3), Bedrock Guardrails (PII trong prompt và output của LLM).

Network
- SG là stateful, chỉ có Allow, gắn vào ENI. NACL là stateless, có Allow/Deny, đánh giá theo số thứ tự rule; nhớ mở ephemeral port 1024–65535 cho traffic trả về. Muốn chặn ngay một IP thì dùng NACL Deny.
- Network Firewall:
- Rule stateful (Suricata) và stateless, lọc theo domain (allowlist), TLS inspection.
- Kiến trúc inspection VPC tập trung + Transit Gateway cho cả traffic north-south và east-west.
- Route 53 Resolver DNS Firewall: chặn truy vấn tới domain độc hại, chống DNS exfiltration.
- Network Access Analyzer: tìm đường truy cập mạng không mong muốn (ví dụ từ Internet vào DB). Reachability Analyzer: kiểm tra kết nối giữa 2 điểm.
- Phân đoạn mạng: subnet isolated không có route ra Internet, chia VPC theo môi trường. Có thể dùng RAM để chia sẻ subnet.

Network Firewall chi tiết:
- Stateless rule group chạy trước (theo priority), action pass/drop/forward to stateful. Traffic phải forward sang stateful thì mới được kiểm tra sâu.
- Stateful rule group: dạng domain list (allowlist/denylist theo SNI và Host), dạng 5-tuple, hoặc Suricata (ví dụ drop tls $HOME_NET any -> $EXTERNAL_NET 443 (tls.sni; content:"bad.com"; sid:1;)). Biến HOME_NET mặc định là CIDR của VPC; kiến trúc tập trung phải sửa lại cho bao hết các VPC.
- Thứ tự đánh giá: strict order (theo priority, khuyến nghị, có default action) hoặc action order (pass → drop → reject → alert).
- TLS inspection cần certificate trong ACM (CA để ký lại cho traffic ra ngoài, hoặc certificate server cho traffic vào).
- Log: alert và flow (và TLS) gửi tới S3, CloudWatch Logs hoặc Firehose.
- Appliance bên thứ ba (Palo Alto, Fortinet...): dùng Gateway Load Balancer (GWLB) + GWLB endpoint. Inspection VPC với TGW phải bật appliance mode để traffic hai chiều đi cùng AZ.

Session Manager trong subnet private không có NAT/IGW: cần interface endpoint com.amazonaws.<region>.ssm, ssmmessages (kênh phiên), ec2messages (agent cũ; từ SSM Agent 3.3.40.0 dùng ssmmessages nếu có), thêm kms (nếu mã hoá phiên) và logs (nếu ghi log CloudWatch), gateway endpoint s3 (log S3, cập nhật agent). SG của endpoint phải cho inbound 443 từ subnet của instance. Instance profile vẫn cần AmazonSSMManagedInstanceCore.

D2: Incident Response

  • Chuẩn bị: IR role có sẵn (break-glass), forensics account riêng, cài sẵn công cụ, tag, AMI chứa công cụ forensics, Shield Advanced + SRT, runbook trong SSM Automation / OpsCenter, notebook (SageMaker AI) để phân tích.
  • EC2 bị xâm nhập (thứ tự thường gặp trong đề):
    1. Thu thập metadata, bật termination protection.
    2. Cô lập: đổi sang SG cô lập không có rule. Lưu ý: kết nối đang được tracked vẫn tiếp tục; nếu muốn cắt ngay thì đổi trước sang SG mở hết (để kết nối thành untracked) rồi mới đổi sang SG rỗng, hoặc dùng NACL Deny.
    3. Tách khỏi ASG (chuyển sang standby hoặc detach) và deregister khỏi ELB.
    4. Snapshot EBS, dump memory.
    5. Gắn tag.
    6. Điều tra trong forensics account.
    7. Xoá mối đe doạ, khôi phục từ AMI hoặc backup sạch.
  • Có thể tự động hoá bằng Automated Forensics Orchestrator for Amazon EC2 (solution, dùng Step Functions).
  • Access key bị lộ: deactivate key → thu hồi session (aws:TokenIssueTime) → xem CloudTrail để biết key đã làm gì → xoá tài nguyên lạ → rotate → kiểm tra AWS Health (AWS_RISK_CREDENTIALS_EXPOSED).
  • S3 bị public: bật Block Public Access → kiểm tra Access Analyzer và Macie → xem CloudTrail data events.
  • IAM user bị chiếm quyền (không chỉ access key): deactivate mọi access key → xoá login profile (mật khẩu console) → gỡ/đổi MFA → gắn policy AWSDenyAll hoặc Deny aws:TokenIssueTime → xem CloudTrail mọi region → xoá resource lạ (user, role, key, Lambda, EC2) → kiểm tra trust policy của role bị sửa để tạo backdoor.
  • Cô lập các loại tài nguyên khác:
Tài nguyên Cô lập (giữ bằng chứng)
Lambda Đặt reserved concurrency = 0 (ngừng chạy, giữ code), lưu code/version, gỡ hoặc thu hẹp execution role, revoke session của role
ECS task Đổi SG của task sang SG cô lập, lưu task definition, ecs stop-task sau khi thu thập (Fargate không snapshot được, dùng GuardDuty Runtime evidence), scale service để thay task
EKS pod/node Network policy deny-all cho pod, cordon node (không nhận pod mới), gắn label, snapshot EBS của node, thu hồi quyền IRSA/Pod Identity
RDS Snapshot ngay, đổi SG chỉ cho máy điều tra, đổi mật khẩu master (qua Secrets Manager), kiểm tra snapshot bị chia sẻ ra ngoài
S3 bucket Block Public Access, Deny trong bucket policy cho principal lạ, giữ object versions, CloudTrail data events

AttackSequence:* Chuỗi tấn công nhiều bước (Critical) Đọc signals và resource bị ảnh hưởng để xác định phạm vi, xử lý theo loại resource
  • Root cause: Detective (behavior graph từ CloudTrail, Flow Logs, GuardDuty, EKS audit; finding group gom finding liên quan). Validate finding để đánh giá phạm vi: kiểm tra finding có phải false positive không (IP scanner nội bộ, pentest đã duyệt), principal đã làm gì khác trong cùng thời gian, resource nào bị chạm tới, có lan sang account khác không. Attack sequence và exposure finding của Security Hub giúp nhìn phạm vi nhanh hơn.
  • Kiểm thử kế hoạch IR: FIS (giả lập sự cố), Resilience Hub, game day. ARC dùng để failover chủ động.

D6: Governance

  • Các loại policy của Organizations:
  • SCP: giới hạn quyền tối đa của principal.
  • RCP: giới hạn quyền tối đa trên resource. Lúc ra mắt (11/2024) chỉ có S3, STS, KMS, SQS, Secrets Manager; nay áp cho khoảng 90 service (thêm DynamoDB, ECR, EFS, EBS, SNS, CloudWatch Logs, EventBridge, Cognito, CloudFront, WAF, Private CA, Roles Anywhere, Security Lake...). Ví dụ: chặn mọi principal ngoài tổ chức bằng aws:PrincipalOrgID.
  • RCP không áp cho: resource ở management account, service-linked role, AWS managed KMS key, quyền kms:RetireGrant. RCP có áp cho root user của account thành viên và cho account delegated admin.
  • Declarative policy: áp cấu hình cho service như EC2 (IMDSv2, chặn public AMI/snapshot, allowed images, VPC Block Public Access, serial console).
  • AI services opt-out policy: không cho AWS dùng dữ liệu để cải thiện dịch vụ AI.
  • Tag policy, backup policy.
  • SCP và RCP không ảnh hưởng tới management account. Muốn ngăn ai thì dùng Deny.
  • SCP chi tiết: chiến lược deny-list (giữ FullAWSAccess + thêm Deny, phổ biến) hoặc allow-list (gỡ FullAWSAccess, chỉ Allow những service được dùng; phải Allow ở mọi cấp từ root xuống account). SCP không áp cho service-linked role. Từ 09/2025 SCP hỗ trợ đầy đủ ngôn ngữ IAM (statement Allow có Condition, ARN resource cụ thể, NotAction; NotResource cho cả Allow và Deny); đề viết trước đó coi Allow trong SCP chỉ có Action + Resource: "*".
  • Control Tower:
  • Controls chia theo mức: mandatory, strongly recommended, elective. Chia theo cơ chế: preventive (SCP/RCP), detective (Config), proactive (CloudFormation Hooks).
  • Có thể tạo custom control, enroll account có sẵn, register OU. Account Factory, AFT.
  • Landing zone tạo sẵn OU Security với account Log Archive + Audit, organization trail, Config. Drift: ai sửa tay SCP/OU do Control Tower quản lý sẽ bị báo drift, phải Repair. Muốn mở rộng tuỳ biến: Customizations for Control Tower (CfCT) hoặc AFT.
  • Delegated administrator: để GuardDuty, Security Hub, Macie, Inspector, Detective, Config, Firewall Manager, Access Analyzer được quản lý từ account Security/Audit, không dùng management account.
  • Root user:
  • Centralized root access: xoá credentials root của các account thành viên, khi cần thì thực hiện tác vụ đặc quyền bằng sts:AssumeRoot (ví dụ mở khoá bucket policy bị khoá nhầm).
  • Bật MFA cho root. Quy trình break-glass gồm credential cất ở nơi an toàn, có alarm khi root đăng nhập.
  • IaC an toàn: StackSets, CloudFormation Guard (policy-as-code), cfn-lint (kiểm tra cú pháp và best practice), Hooks. Terraform cũng được tính là công cụ bên thứ ba.
  • Tag: dùng cho ABAC, phân bổ chi phí, nhóm resource. Tag policy chuẩn hoá tag.
  • Firewall Manager: cần Organizations + Config + admin account. Quản lý tập trung WAF, Shield Advanced, SG, Network Firewall, DNS Firewall và firewall bên thứ ba.
  • Chia sẻ tài nguyên: RAM (subnet, TGW, Resolver rule, Private CA, prefix list...), Service Catalog (product đã chuẩn hoá).
  • Compliance và audit:
  • Config rule + remediation + aggregator. Security Hub.
  • Config rule: managed (AWS viết sẵn) hoặc custom (Lambda hoặc Guard policy). Trigger: configuration change (khi resource đổi) hoặc periodic (1, 3, 6, 12, 24 giờ). Remediation chạy SSM Automation document (thủ công hoặc tự động, có retry). Conformance pack = gói rule + remediation, deploy cho cả tổ chức.
  • Trusted Advisor: có nhóm check Security (SG mở, MFA root, access key lộ, bucket public...). Business/Enterprise Support có đủ check; tích hợp Security Hub CSPM và gửi sự kiện qua EventBridge.
  • AWS User Notifications: nơi cấu hình tập trung thông báo (từ EventBridge, Health, CloudWatch alarm...) tới email, chat (Slack/Teams), mobile app.
  • Audit Manager: tự động thu thập bằng chứng theo framework (PCI, HIPAA, SOC 2...).
  • Artifact: tải báo cáo compliance của AWS, ký các thoả thuận như BAA.
  • Well-Architected Tool: đánh giá theo Security pillar.

Mẹo làm bài Specialty

  • Ưu tiên đáp án theo thứ tự: least privilege, phòng ngừa (preventive) trước, phát hiện (detective) sau, tự động hoá, tập trung quản lý ở mức tổ chức.
  • Từ khoá trong đề gợi ý đáp án:
  • "Không để AWS truy cập key": dùng CloudHSM hoặc XKS.
  • "Kiểm soát vòng đời key material, xoá ngay": dùng imported key material.
  • "Chia sẻ cross-account": dùng customer managed key.
  • "Real-time": dùng EventBridge.
  • "Lưu log lâu dài, không sửa được": S3 + Object Lock + CloudTrail validation.
  • Câu ordering: xác định bước đầu tiên (thường là thu thập bằng chứng hoặc cô lập) và bước cuối (khôi phục hoặc xem lại) trước, sau đó sắp phần giữa.
  • Đáp án nào yêu cầu tắt hoặc xoá tài nguyên bị xâm nhập ngay lập tức thường sai, vì sẽ mất bằng chứng forensics.
