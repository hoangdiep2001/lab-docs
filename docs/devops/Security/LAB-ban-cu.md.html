Lab 9: Authorization (Skill 4.2.1–4.2.5)

9a. Bài luyện đánh giá policy (tự trả lời trước, rồi kiểm tra bằng Policy Simulator)

# Tình huống Kết quả
1 Identity policy Allow s3:*; SCP không có s3 trong danh sách Allow (SCP dạng allow-list) Deny (SCP không cho phép)
2 Identity policy Allow s3:GetObject; bucket policy Deny khi không có aws:SecureTransport; request dùng HTTP Deny
3 Role có AdministratorAccess; permission boundary chỉ có s3:*; gọi ec2:RunInstances Deny
4 Account A gọi S3 ở account B; bucket policy B cho phép A; identity policy ở A không có quyền S3 Deny (cross-account cần cả 2 phía)
5 Cùng account; bucket policy Allow trực tiếp cho role ARN; identity policy không có quyền S3 Allow (resource policy đủ trong cùng account)
6 KMS key policy chỉ có statement cho admin, không có root; IAM policy Allow kms:Decrypt Deny (key policy không ủy quyền cho IAM)
7 AssumeRole có session policy chỉ cho s3:GetObject; role có s3:*; gọi s3:PutObject Deny
8 SCP Deny ec2:* khi aws:RequestedRegion khác us-east-1; user ở management account gọi trong eu-west-1 Allow (SCP không áp lên management account)

10c. BYOK: imported key material

EXT=$(aws kms create-key --origin EXTERNAL --description byok --query KeyMetadata.KeyId --output text)
aws kms get-parameters-for-import --key-id $EXT --wrapping-algorithm RSAES_OAEP_SHA_256 \
  --wrapping-key-spec RSA_2048 > params.json
python -c "import json,base64;d=json.load(open('params.json'));open('wrap.der','wb').write(base64.b64decode(d['PublicKey']));open('token.bin','wb').write(base64.b64decode(d['ImportToken']))"
openssl rand -out material.bin 32                     # key material của bạn: TỰ GIỮ bản gốc
openssl pkeyutl -encrypt -in material.bin -out enc.bin -inkey wrap.der -keyform DER -pubin \
  -pkeyopt rsa_padding_mode:oaep -pkeyopt rsa_oaep_md:sha256
aws kms import-key-material --key-id $EXT --encrypted-key-material fileb://enc.bin \
  --import-token fileb://token.bin --expiration-model KEY_MATERIAL_EXPIRES --valid-to 2026-12-31T00:00:00Z
aws kms describe-key --key-id $EXT        # KeyState: Enabled, Origin: EXTERNAL
aws kms delete-imported-key-material --key-id $EXT     # key chuyển sang PendingImport NGAY LẬP TỨC
# Import lại ĐÚNG material.bin (cần lấy params mới) thì key dùng được trở lại; dữ liệu cũ vẫn giải mã được

On-demand rotation cho imported key material (có từ 06/2025, chỉ key symmetric):

# 1) Import lại material cũ (nếu đã xoá ở bước trên) để key về Enabled
# 2) Sinh material MỚI, lấy wrapping key + token mới, wrap như trên
openssl rand -out material2.bin 32
aws kms get-parameters-for-import --key-id $EXT --wrapping-algorithm RSAES_OAEP_SHA_256 \
  --wrapping-key-spec RSA_2048 > params2.json
#    (tách PublicKey/ImportToken ra wrap2.der, token2.bin như lệnh python ở trên, rồi openssl pkeyutl ra enc2.bin)
aws kms import-key-material --key-id $EXT --encrypted-key-material fileb://enc2.bin \
  --import-token fileb://token2.bin --expiration-model KEY_MATERIAL_DOES_NOT_EXPIRE \
  --import-type NEW_KEY_MATERIAL --key-material-description "lab rotation 1"
aws kms list-key-rotations --key-id $EXT      # material mới ở trạng thái PENDING_ROTATION
aws kms rotate-key-on-demand --key-id $EXT    # material mới thành current; dữ liệu cũ vẫn giải mã bằng material cũ

10d. Multi-Region key + chia sẻ snapshot cross-account

MRK=$(aws kms create-key --multi-region --query KeyMetadata.KeyId --output text)    # ID bắt đầu bằng mrk-
aws kms replicate-key --key-id $MRK --replica-region us-west-2
# Mã hoá ở us-east-1, giải mã ở us-west-2 bằng replica: chạy được mà không cần gọi chéo region

Chia sẻ snapshot EBS đã mã hoá:
1. Tạo snapshot dùng CMK (không dùng được aws/ebs).
2. Thêm account đích vào key policy (kms:Decrypt, kms:CreateGrant, kms:DescribeKey, kms:ReEncrypt*).
3. aws ec2 modify-snapshot-attribute --attribute createVolumePermission --operation-type add --user-ids <dest>.
4. Ở account đích, copy snapshot và mã hoá lại bằng key của account đích.

Ghi nhớ cho đề thi: CloudHSM key store (key nằm trong HSM của bạn trên AWS) khác XKS (key nằm ngoài AWS). Cả hai không hỗ trợ automatic rotation và key asymmetric. Không cần tạo thật vì tốn phí, nhưng phải nắm các điểm này.

Lab L16: Network Firewall chuyên sâu (Skill 3.3.1, 3.3.4)

Nâng cấp bước 3 của Lab 7 thành bài bắt buộc. Kiến trúc tối thiểu: VPC có firewall subnet riêng, subnet workload định tuyến 0.0.0.0/0 → firewall endpoint, firewall subnet → NAT/IGW, và route table của IGW (edge association) trả traffic về firewall endpoint.

  1. Stateless rule group (console → Network Firewall → Rule groups → Stateless): rule priority 10 drop TCP port 23 (telnet); rule priority 100 forward to stateful cho mọi traffic còn lại.
  2. Stateful rule group dạng Suricata, strict order:
    bash cat > rules.suricata <<'EOF' drop tls $HOME_NET any -> $EXTERNAL_NET 443 (tls.sni; content:"example.com"; endswith; nocase; msg:"block example.com"; sid:1001; rev:1;) alert http $HOME_NET any -> $EXTERNAL_NET 80 (http.host; content:"neverssl.com"; msg:"plain http seen"; sid:1002; rev:1;) pass tls $HOME_NET any -> $EXTERNAL_NET 443 (tls.sni; dotprefix; content:".amazonaws.com"; endswith; sid:1003; rev:1;) EOF aws network-firewall create-rule-group --rule-group-name lab16-suricata --type STATEFUL --capacity 100 \ --rules file://rules.suricata --stateful-rule-options RuleOrder=STRICT_ORDER
  3. Stateful rule group dạng domain list (console): allowlist .github.com, .amazonaws.com, kiểu HTTP_HOST + TLS_SNI.
