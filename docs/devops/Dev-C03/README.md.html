Điểm mới của C03 so với C02 (bắt buộc học)

  • Task 2.3 (mới hoàn toàn): bảo mật khi tích hợp AI: quản lý quyền truy cập AI service, VPC endpoint/PrivateLink, dữ liệu input/output không bị dùng để train model, lọc input/output (content filter, che PII/PHI, denied topics, chống prompt injection), bảo mật AI agent (phân quyền tool-use, cô lập session, human-in-the-loop), che dữ liệu nhạy cảm trong log.
  • AI tools xuất hiện ở mọi domain: sinh code, review code, sinh test, hỗ trợ CI/CD, phân tích lỗi, gợi ý tối ưu. In-scope của C03 ghi Kiro, Amazon Bedrock AgentCore, Amazon Quick (không còn ghi Amazon Q Developer). Xem mục AI tools & services C03.
  • Container: build/quản lý image (ECR, Dockerfile, tag, lifecycle policy), deploy ECS task definition, EKS manifest, Fargate, rolling update.
  • Presigned URL cho S3 và CloudFront.
  • Bỏ phần "Unit testing bằng SAM" khỏi D1; phần này giờ nằm ở D3. Phần "tối ưu hiệu năng Lambda" chuyển sang D4.
  • D4 tăng từ 18% lên 22%.

Cheat sheet Domain 3: Testing and Deployment

Task 3.1: Chuẩn bị artifact

  • Lambda: .zip tối đa 50 MB khi upload trực tiếp, 250 MB sau khi giải nén. Container image tối đa 10 GB. Tối đa 5 layers. Tổng biến môi trường tối đa 4 KB.
  • ECR: đăng nhập bằng aws ecr get-login-password | docker login …, bật tag immutability, lifecycle policy để xoá image cũ, image scanning.
  • Config theo môi trường:
  • Parameter Store: bản Standard miễn phí, tối đa 4 KB; bản Advanced tối đa 8 KB; tổ chức theo hierarchy /app/prod/db; không tự rotate.
  • Secrets Manager: tự rotate bằng Lambda, tích hợp sẵn với RDS.
  • AppConfig: feature flag, validator, deployment strategy, tự rollback khi alarm kích hoạt.
  • API Gateway: mỗi stage có URL riêng (/dev, /prod). Stage variables, ví dụ function:${stageVariables.alias}, cần quyền invoke cho từng alias. Mọi thay đổi phải deploy mới có hiệu lực. Loại endpoint: Edge, Regional, Private. Có custom domain. Cache theo stage: TTL mặc định 300 giây, tối đa 3600 giây.

Task 3.2: Testing

  • SAM: sam local invoke -e event.json, sam local start-api, sam local generate-event s3 put, sam sync --watch.
  • CDK: cdk synth, cdk diff. Test bằng assertions (Template.fromStack(stack).hasResourceProperties(...)).
  • Mock API: dùng API Gateway mock integration để trả response cố định, giả lập phụ thuộc bên ngoài.
  • Môi trường: Lambda alias (dev/prod), container image tag, Amplify branch (mỗi nhánh là một môi trường), Copilot environment (khái niệm; Copilot CLI hết hỗ trợ 06/2026), API Gateway stage.
  • [C03] AI: Kiro agent hook sinh/cập nhật unit test khi lưu file, chạy regression test, phân tích kết quả và độ phủ test (pytest --cov). Test do AI sinh vẫn phải review.

Task 3.3: CI/CD

  • CodeBuild: file buildspec.yml ở thư mục gốc, các phase install → pre_build → build → post_build, cùng artifacts, cache (S3 hoặc local), env (lấy từ Parameter Store hoặc Secrets Manager).
  • CodeDeploy: file appspec.yml.
  • Hooks trên EC2: ApplicationStop → DownloadBundle → BeforeInstall → Install → AfterInstall → ApplicationStart → ValidateService.
  • Hooks cho Lambda: BeforeAllowTraffic, AfterAllowTraffic.
  • Hooks cho ECS: BeforeInstall → AfterInstall → AfterAllowTestTraffic → BeforeAllowTraffic → AfterAllowTraffic.
  • Deployment config: Canary10Percent5Minutes, Linear10PercentEvery1Minute, AllAtOnce.
  • Rollback thực chất là một deployment mới dùng lại revision tốt gần nhất. Có thể tự động khi deploy lỗi hoặc khi CloudWatch alarm kích hoạt.
  • CodePipeline: gồm stage và action, artifact lưu trong S3, bước manual approval gửi thông báo qua SNS. Kích hoạt bằng CodeConnections (GitHub, Bitbucket) hoặc EventBridge. Chuyển lần lượt qua các môi trường dev, staging, prod.
  • SAM + CodeDeploy: dùng AutoPublishAlias + DeploymentPreference (Type: Canary10Percent5Minutes, Alarms, Hooks: PreTraffic/PostTraffic).
  • CloudFormation:
  • Chỉ có Resources là bắt buộc. Hàm hay gặp: !Ref, !GetAtt, !Sub, !ImportValue.
  • Cross-stack (Export/Import) và nested stack. Change set để xem trước thay đổi. DeletionPolicy: Delete (mặc định với đa số tài nguyên), Retain, RetainExceptOnCreate, Snapshot (RDS, EBS, ElastiCache…). UpdateReplacePolicy áp dụng khi tài nguyên bị thay thế lúc update.
  • CreationPolicy + cfn-signal. Stack policy. Mặc định tự rollback khi lỗi. StackSets cho nhiều account hoặc region.
  • ECS/EKS:
  • Task definition gồm image, CPU/memory, port, task role (quyền cho ứng dụng) và execution role (quyền kéo image và ghi log).
  • Fargate là serverless. Rolling update điều khiển bằng minimumHealthyPercent/maximumPercent, circuit breaker tự rollback. Blue/green trên ECS: có sẵn trong ECS từ 07/2025 (strategy: BLUE_GREEN, bake time, lifecycle hook Lambda; 10/2025 thêm LINEAR, CANARY), hoặc cách cũ dùng CodeDeploy (đề cũ chọn cách này).
  • EKS: file manifest khai báo Deployment/Service, rolling update.
  • Chiến lược deploy:
  • All-at-once: nhanh nhất nhưng có downtime.
  • Rolling: deploy từng đợt.
  • Canary: ít ảnh hưởng nhất.
  • Blue/green: rollback nhanh nhất.
  • Elastic Beanstalk Immutable: an toàn nhất trên Beanstalk.
  • Source control: quản lý version bằng branch, tag/label, Git tag, rồi chọn version tương ứng để release.
  • [C03] AI cho CI/CD: tự động hoá phê duyệt deploy, tạo môi trường, kiểm tra sau khi deploy. Ví dụ: Kiro CLI chạy trong CodeBuild để review diff PR; sau deploy chạy smoke test và nhờ AI tóm tắt alarm/log; vẫn giữ manual approval cho prod.

Deployment bổ sung

  • CDK: construct L1 (Cfn*), L2 (default hợp lý, grant*() sinh IAM least privilege), L3/pattern. Lệnh cdk init/bootstrap/synth/diff/deploy/destroy. Phải bootstrap mỗi account/region (stack CDKToolkit). Test: aws-cdk-lib/assertions (Template.fromStack, hasResourceProperties). Test Lambda local: sam local invoke -t cdk.out/<Stack>.template.json.
  • CloudFormation nâng cao: Parameters (kiểu AWS::SSM::Parameter::Value<String> để lấy giá trị từ Parameter Store), Mappings + !FindInMap, Conditions + !If, !Select/!Split/!Join, !GetAZs. Custom resource (Lambda) cho việc CFN không hỗ trợ. Nested stack (tái sử dụng template, deploy cùng nhau) và cross-stack Export/!ImportValue (không xoá được stack đang bị import). cfn-init/cfn-hup/cfn-signal cho EC2. Drift detection. Dynamic reference {{resolve:secretsmanager:...}}.
  • CodePipeline V2: trigger filter theo branch/tag/path/PR, pipeline variables, stage rollback (thủ công hoặc tự động khi stage lỗi), stage conditions (CloudWatch alarm, khung giờ deploy, lệnh), tính phí theo phút action.
  • CodeBuild: test report (JUnit…) và coverage report, batch build, privilegedMode để build Docker, chạy trong VPC.
  • CodeArtifact: repo package (pip/npm/Maven/NuGet), upstream + external connection (public:pypi) để cache package công khai, aws codeartifact login --tool pip lấy token 12 giờ.
  • ECS: Express Mode (AWS khuyến nghị thay Copilot CLI đã hết hỗ trợ 06/2026): một lệnh tạo service + ALB HTTPS + auto scaling + rollback alarm. Circuit breaker (rollback=true). Native blue/green (BLUE_GREEN, bake time, lifecycle hook ở POST_TEST_TRAFFIC_SHIFT…). Secret cho container: secrets trong task definition lấy từ SSM/Secrets Manager (execution role cần quyền đọc). ECS Exec để vào container debug.
  • EKS: Deployment (replicas, strategy.rollingUpdate.maxSurge/maxUnavailable), Service, Ingress (AWS Load Balancer Controller tạo ALB). kubectl rollout status/undo. readinessProbe fail → không nhận traffic; livenessProbe fail → restart. Quyền AWS cho pod: EKS Pod Identity hoặc IRSA.
  • ECR: tag immutability, lifecycle policy, scan basic hoặc enhanced (Inspector, quét liên tục), replication cross-region/cross-account, pull-through cache cho Docker Hub/ECR Public.
  • Amplify Hosting: mỗi branch = một môi trường có URL riêng, PR preview, Gen 2 backend định nghĩa bằng TypeScript.

Bảng số liệu phải thuộc

⚠️ Cập nhật 2025–2026: payload tối đa của Lambda async, SQS và EventBridge đã tăng từ 256 KB lên 1 MB. SNS vẫn là 256 KB. Đề luyện cũ (C02) có thể vẫn ghi 256 KB. Nếu đề thật hỏi theo số cũ, hãy chọn đáp án hợp lý nhất trong các lựa chọn.

Dịch vụ Giới hạn
Lambda Timeout tối đa 15 phút. Memory 128 MB – 10,240 MB. /tmp 512 MB – 10 GB. Payload sync 6 MB (request và response), async 1 MB. Biến môi trường tổng 4 KB. Concurrency mặc định 1,000 mỗi region (soft limit)
Lambda async Retry mặc định 2 lần. Event được giữ tối đa 6 giờ (MaximumEventAgeInSeconds)
SQS Message 1 MiB (lớn hơn thì dùng Extended Client Library, lưu payload trong S3). Retention 1 phút – 14 ngày (mặc định 4 ngày). Visibility timeout mặc định 30 giây, tối đa 12 giờ. Delay tối đa 15 phút. Long polling tối đa 20 giây. Thời gian dedup của FIFO là 5 phút
SQS FIFO 300 msg/s mỗi API, 3,000 msg/s khi gửi batch. High throughput mode: tới hàng chục nghìn msg/s (tối đa ~70,000 msg/s ở một số region), throughput chia theo message group ID
SNS Message 256 KB. Filter policy theo message attributes hoặc message body
Kinesis Data Streams Mỗi shard: ghi 1 MB/s hoặc 1,000 record/s, đọc 2 MB/s (dùng chung cho mọi consumer). Enhanced fan-out: 2 MB/s cho từng consumer. Retention 24 giờ (mặc định) – 365 ngày
DynamoDB Item tối đa 400 KB. BatchWriteItem 25 item. BatchGetItem 100 item / 16 MB. Query/Scan trả tối đa 1 MB mỗi trang. LSI tối đa 5 (chỉ tạo lúc tạo bảng). GSI mặc định 20. Streams giữ 24 giờ. Transaction tối đa 100 item
API Gateway Payload 10 MB. Integration timeout mặc định 29 giây (REST Regional/private có thể xin tăng). Throttle mặc định cho account 10,000 rps, burst 5,000. Cache TTL mặc định 300 giây, tối đa 3,600 giây. Cache của Lambda authorizer mặc định 300 giây
S3 Object tối đa 5 TB. Một lần PUT tối đa 5 GB. Nên dùng multipart khi > 100 MB, bắt buộc khi > 5 GB. Mỗi prefix: 3,500 PUT / 5,500 GET mỗi giây
Presigned URL Ký bằng IAM user: tối đa 7 ngày. Ký bằng role/STS: hết hạn khi session hết hạn, kể cả khi đặt expires-in dài hơn
KMS Encrypt tối đa 4 KB. Quota request dùng chung trong account và region (từ 5,500 rps, tới vài chục nghìn rps tuỳ region). Vượt quota sẽ bị ThrottlingException
STS AssumeRole từ 15 phút đến max session của role (tối đa 12 giờ). Role chaining tối đa 1 giờ
Parameter Store Standard 4 KB (miễn phí, 10,000 parameter). Advanced 8 KB (tính phí, có parameter policy như TTL)
CloudWatch Metric chuẩn 1 phút (EC2 basic 5 phút). Custom metric high-resolution 1 giây. Log mặc định giữ vĩnh viễn
X-Ray Sampling mặc định: request đầu tiên mỗi giây + 5% số request còn lại. Annotation tối đa 50 mỗi trace. Daemon dùng UDP 2000 (daemon/SDK hết hỗ trợ 25/02/2027, thay bằng ADOT/CloudWatch agent nhận OTLP)

Cheat sheet Domain 1: Development with AWS Services (30%)

Lambda

  • Gọi đồng bộ (API Gateway, ALB, SDK RequestResponse): lỗi trả về cho client, client tự retry.
  • Gọi bất đồng bộ (S3, SNS, EventBridge, --invocation-type Event): Lambda tự retry 2 lần. Xử lý lỗi bằng Destinations (OnSuccess/OnFailure tới SQS, SNS, Lambda, EventBridge; OnFailure còn hỗ trợ S3) hoặc DLQ (chỉ SQS/SNS, chỉ có event gốc).
  • Event source mapping (SQS, Kinesis, DynamoDB Streams, MSK): Lambda chủ động poll.
  • SQS: BatchSize, MaximumBatchingWindowInSeconds, ReportBatchItemFailures (chỉ retry message lỗi), MaximumConcurrency (giới hạn số Lambda chạy cho mỗi queue). DLQ cấu hình trên queue, không phải trên Lambda.
  • Kinesis/DynamoDB Streams: một batch lỗi sẽ chặn cả shard cho tới khi thành công hoặc record hết hạn. Xử lý bằng BisectBatchOnFunctionError, MaximumRetryAttempts, MaximumRecordAgeInSeconds, on-failure destination. Tăng tốc bằng ParallelizationFactor (1–10). Metric cần theo dõi: IteratorAge.
  • Event filtering: lọc event ngay ở ESM nên không tốn tiền invoke.
  • Trong VPC: Lambda không có internet. Cần NAT Gateway (đặt ở public subnet) hoặc VPC endpoint. Execution role cần AWSLambdaVPCAccessExecutionRole.
  • Function URL: endpoint HTTPS riêng cho hàm, auth NONE hoặc AWS_IAM. Cần throttle, WAF, usage plan thì dùng API Gateway.
  • Lambda@Edge (Node/Python, tối đa 5–30 giây, truy cập mạng được) và CloudFront Functions (JS, dưới 1 ms, chỉ sửa header/URL, rẻ hơn rất nhiều).
  • SnapStart (Java 11+, Python 3.12+, .NET 8+; từ 09/2026 hỗ trợ cả container image): giảm cold start mà không tốn phí provisioned concurrency. Code phải chịu được việc restore từ snapshot (ví dụ không được tạo số ngẫu nhiên hay mở kết nối trong phần init rồi dùng lại mãi).
  • Code khởi tạo (SDK client, kết nối DB) đặt ngoài handler để dùng lại giữa các lần gọi.
  • Layer: dùng chung thư viện. Extension: chạy song song với hàm (ví dụ AppConfig, Parameters and Secrets extension có cache).

API Gateway (dành cho developer)

  • REST API: đủ tính năng (usage plan, API key, cache, WAF, request validation, mapping template, private endpoint). HTTP API: rẻ hơn, nhanh hơn, có JWT authorizer, ít tính năng hơn. WebSocket API: kết nối 2 chiều (chat, realtime).
  • Authorizer:
  • IAM (SigV4): dùng cho client/service nội bộ trong AWS.
  • Cognito User Pool authorizer: client gửi JWT.
  • Lambda authorizer: loại TOKEN (chỉ đọc header token) hoặc REQUEST (header, query string, stage variables, context). Trả về IAM policy. Có cache (sai cache key thì user này nhận quyền của user khác).
  • Usage plan + API key: giới hạn throttle và quota cho từng khách hàng. API key không phải cơ chế xác thực.
  • Resource policy: giới hạn theo IP, VPC/VPC endpoint (bắt buộc cho private API), hoặc account.
  • CORS: với proxy integration, Lambda phải tự trả header Access-Control-Allow-Origin. Bật CORS trên console chỉ tạo method OPTIONS.
  • Proxy (Lambda nhận toàn bộ request) và non-proxy (dùng mapping template VTL để biến đổi request và response).
  • Mã lỗi: 400 request sai, 403 bị từ chối (authorizer, resource policy, WAF, sai path), 429 bị throttle, 502 Lambda trả sai định dạng, 503 backend không sẵn sàng, 504 quá integration timeout.

DynamoDB (bổ sung cho Lab 6)

  • Throughput: on-demand (không biết trước tải, trả theo request) và provisioned + auto scaling (tải ổn định, rẻ hơn).
  • GSI bị throttle có thể làm ghi vào bảng chính cũng bị throttle. WCU của GSI cần ≥ WCU của bảng.
  • BatchWriteItem và BatchGetItem có thể trả về UnprocessedItems hoặc UnprocessedKeys. Phải retry phần đó với exponential backoff.
  • Giảm RCU: dùng ProjectionExpression (chỉ lấy thuộc tính cần) không giảm RCU, vì RCU tính theo kích thước item. Muốn giảm thì thiết kế item nhỏ hơn, hoặc dùng GSI với projection nhỏ, hoặc cache.
  • Streams view type: KEYS_ONLY, NEW_IMAGE, OLD_IMAGE, NEW_AND_OLD_IMAGES. Muốn so sánh trước và sau khi sửa thì chọn NEW_AND_OLD_IMAGES.
  • TTL: item hết hạn bị xoá trong vòng vài ngày, không tốn WCU, và vẫn xuất hiện trong Streams. Query cần lọc thêm các item đã hết hạn nhưng chưa bị xoá.
  • Global Tables: nhiều region cùng ghi. PartiQL: truy vấn kiểu SQL.

S3 cho developer

  • Strong read-after-write consistency cho mọi thao tác.
  • Upload nhanh hơn: multipart upload, Transfer Acceleration (upload từ xa qua edge location). Tải nhanh hơn: byte-range fetch.
  • Event notifications gửi tới SQS, SNS, Lambda, hoặc EventBridge (EventBridge lọc được nhiều điều kiện hơn và gửi được tới nhiều đích).
  • CORS cấu hình trên bucket khi trang web ở domain khác gọi trực tiếp tới bucket.
  • Upload trực tiếp từ trình duyệt mà không đi qua backend: presigned URL (PUT) hoặc presigned POST.

Cheat sheet Domain 2: Security (26%)

IAM & STS

  • Cùng account: identity policy hoặc resource policy cho phép là đủ. Khác account: cần cả 2 phía cho phép (identity policy bên gọi và resource policy hoặc trust policy bên nhận).
  • iam:PassRole: cần có khi gán role cho dịch vụ (Lambda, EC2, ECS, CodeBuild...). Lỗi khi tạo Lambda kèm role thường do thiếu quyền này.
  • Condition key hay gặp: aws:SourceIp, aws:SecureTransport (ép HTTPS), aws:MultiFactorAuthPresent, aws:PrincipalOrgID, aws:SourceVpce, aws:RequestedRegion, kms:ViaService.
  • Policy variable: ${aws:username}. Với Identity Pool: ${cognito-identity.amazonaws.com:sub} để mỗi user chỉ truy cập prefix S3 của mình.
  • STS:
  • AssumeRole: cross-account. Dùng thêm ExternalId khi cho bên thứ ba assume (chống confused deputy).
  • AssumeRoleWithWebIdentity: đăng nhập qua OIDC. Với mobile/web thì ưu tiên Cognito Identity Pool.
  • AssumeRoleWithSAML: đăng nhập qua SAML.
  • GetSessionToken: lấy credentials tạm có MFA cho IAM user.
  • GetCallerIdentity: kiểm tra đang chạy với danh tính nào.
  • DecodeAuthorizationMessage: đọc lý do bị từ chối.

Cognito

  • User Pool: đăng ký, đăng nhập, MFA, quên mật khẩu, federation (Google, Facebook, SAML, OIDC), Managed login/Hosted UI. Trả về ID token (thông tin user), access token (scope, gọi API), refresh token.
  • Lambda trigger của User Pool: pre sign-up (tự xác nhận user, chặn domain email), post confirmation (ghi user vào DB), pre token generation (thêm claim vào token), custom auth challenge, migrate user (chuyển user từ hệ thống cũ khi họ đăng nhập).
  • Identity Pool: đổi token (User Pool, Google, SAML, cả khách vãng lai) lấy AWS credentials tạm thời. Role-based access: chọn role theo group hoặc theo rule trên claim.
  • ALB có thể xác thực trực tiếp với Cognito hoặc OIDC (action authenticate-cognito), backend không cần viết code đăng nhập.

KMS & mã hoá

  • Các loại key: AWS owned (không thấy, không audit được), AWS managed (aws/s3, aws/lambda..., tự rotate hằng năm, không sửa được key policy, không dùng cross-account được), customer managed (tự quản lý key policy, grant, rotation tuỳ chọn; dùng được cross-account).
  • Mọi key bắt buộc có key policy. Cấp quyền tạm thời cho dịch vụ thì dùng grant.
  • GenerateDataKey trả về plaintext + ciphertext (mã hoá ngay). GenerateDataKeyWithoutPlaintext chỉ trả về ciphertext (dùng khi mã hoá sau, ở hệ thống khác).
  • Encryption context: cặp key-value ràng buộc vào ciphertext, giải mã phải đưa đúng. Xuất hiện trong CloudTrail để audit.
  • Giảm số lần gọi KMS và chi phí: S3 Bucket Key (giảm tới 99%), data key caching của AWS Encryption SDK.
  • S3:
  • SSE-S3 là mặc định cho mọi object mới (từ 2023).
  • SSE-KMS: header x-amz-server-side-encryption: aws:kms. Người upload/download cần quyền kms:GenerateDataKey/kms:Decrypt.
  • DSSE-KMS: mã hoá 2 lớp.
  • SSE-C: gửi key trong mỗi request, bắt buộc HTTPS, AWS không lưu key.
  • Ép HTTPS cho bucket: bucket policy Deny khi aws:SecureTransport = false.
  • Secrets Manager dùng cross-account phải mã hoá secret bằng customer managed key, kèm resource policy trên secret.

Phân phối nội dung an toàn

  • S3 presigned URL: một object, quyền của người ký.
  • CloudFront signed URL: một file. Signed cookie: nhiều file (ví dụ cả thư viện video), không đổi URL. Dùng key group (khuyến nghị, quản lý bằng IAM) thay vì CloudFront key pair của root.
  • OAC (Origin Access Control): chỉ CloudFront mới đọc được bucket, user không vào thẳng S3 được.
  • Certificate (ACM): cho CloudFront và API Gateway edge-optimized phải tạo ở us-east-1. Cho ALB và API Gateway Regional thì tạo ở cùng region với tài nguyên.

Certificate, SSH key, IAM evaluation, KMS, Secrets (bổ sung)

  • ACM public: miễn phí, DNS validation thì tự gia hạn, không lấy được private key (trừ loại exportable có phí, 2025). Cert import: không tự gia hạn, tự theo dõi hạn (EventBridge ACM Certificate Approaching Expiration, Config rule). AWS Private CA: cert nội bộ (mTLS, IoT, Roles Anywhere), tính phí theo tháng mỗi CA. Dev/test: cert tự ký bằng openssl.
  • SSH key (2.2.5): ec2 create-key-pair (AWS sinh, private key trả về một lần) hoặc import-key-pair (tự sinh bằng ssh-keygen -t ed25519, AWS chỉ giữ public key). Không cần key: Session Manager, EC2 Instance Connect (key tạm 60 giây).
  • Thứ tự đánh giá policy: Deny tường minh ở bất kỳ đâu → thắng. Sau đó phải được cho phép bởi: SCP/RCP (nếu có Organizations) → resource-based policy → permission boundary → session policy → identity-based policy. Không có Allow nào thì mặc định Deny. NotAction/NotResource dùng cho "mọi thứ trừ…".
  • ABAC: so khớp tag, ví dụ aws:ResourceTag/project = ${aws:PrincipalTag/project}. Session policy truyền vào AssumeRole để thu hẹp quyền tạm thời.
  • KMS: rotation tự động cho customer managed key (mặc định 1 năm, chọn được 90–2560 ngày; rotate ngay bằng RotateKeyOnDemand). Multi-Region key để mã hoá ở region này, giải mã ở region khác. Key asymmetric (ký/verify, mã hoá ngoài AWS) và HMAC. Giới hạn Encrypt 4 KB → dữ liệu lớn dùng envelope encryption (GenerateDataKey, AWS Encryption SDK).
  • Secrets Manager rotation: Lambda rotation 4 bước createSecret → setSecret → testSecret → finishSecret, label AWSPENDING → AWSCURRENT → AWSPREVIOUS. Chiến lược single user (đơn giản, có khoảng ngắn kết nối cũ lỗi) và alternating users (2 user luân phiên, không gián đoạn). Ứng dụng đọc secret qua Parameters and Secrets Lambda extension có cache.
  • Cognito OAuth: Authorization code + PKCE cho web/mobile; client credentials cho machine-to-machine (cần resource server + custom scope, app client có secret). App client có secret thì gọi API phải gửi SECRET_HASH. Token: ID token và access token mặc định 1 giờ (5 phút – 1 ngày), refresh token mặc định 30 ngày; thu hồi bằng RevokeToken/GlobalSignOut. Groups → gán IAM role qua Identity Pool, claim cognito:groups trong token.

CloudWatch Logs & Lambda logging

  • Advanced logging controls của Lambda: log dạng JSON, đặt log level (application và system) không cần sửa code, chọn log group tuỳ ý.
  • Metric filter biến log thành metric (chỉ tính từ lúc tạo). Subscription filter đẩy log real-time tới Lambda, Kinesis, Firehose, OpenSearch.
  • Live Tail xem log trực tiếp khi debug.
  • Logs Insights: fields, filter, stats ... by bin(5m), sort, limit, parse, dedup, unmask (xem dữ liệu đã mask, cần quyền logs:Unmask). Log class Infrequent Access rẻ hơn cho log ít truy vấn. Log REPORT của Lambda có @duration, @billedDuration, @maxMemoryUsed, @initDuration (chỉ có khi cold start).
  • Alarm có 3 trạng thái: OK, ALARM, INSUFFICIENT_DATA. Composite alarm kết hợp nhiều alarm để giảm cảnh báo nhiễu.

X-Ray & tracing

  • Segment (một service), subsegment (gọi downstream, như DynamoDB, HTTP), trace (toàn bộ request, xuyên service qua header X-Amzn-Trace-Id).
  • Annotation (index được, dùng để filter và group) và metadata (không index). Cả hai đều phải ghi bằng SDK.
  • Quyền: AWSXRayDaemonWriteAccess (xray:PutTraceSegments, xray:PutTelemetryRecords).
  • Nơi chạy: Lambda bật Active tracing; API Gateway bật tracing ở stage; ECS chạy ADOT collector/CloudWatch agent dạng sidecar (cách cũ: X-Ray daemon sidecar); EC2 cài CloudWatch agent hoặc daemon; Elastic Beanstalk bật trong cấu hình.
  • Đổi sampling (ví dụ trace nhiều hơn cho một API) bằng sampling rule trên console, không cần deploy lại code.
  • X-Ray SDK và daemon: maintenance từ 25/02/2026, hết hỗ trợ 25/02/2027. Dịch vụ X-Ray vẫn chạy (nhận OTLP, Transaction Search tìm theo span). Dự án mới dùng ADOT / OpenTelemetry + CloudWatch Application Signals (SLO, service map). Trace context: header X-Amzn-Trace-Id hoặc W3C traceparent.

Alert & quota (4.2.3)

  • Sắp chạm quota: Service Quotas → Create CloudWatch alarm (metric AWS/Usage, metric math SERVICE_QUOTA()), ví dụ 80% concurrent executions của Lambda. Xin tăng: Request quota increase.
  • Deploy xong/lỗi: EventBridge rule cho CodePipeline Pipeline Execution State Change, CodeDeploy Deployment State-change Notification, CodeBuild state change → SNS.
  • Composite alarm (AND/OR) giảm báo nhiễu. Metric math (ví dụ tỉ lệ lỗi). Anomaly detection khi ngưỡng thay đổi theo giờ/ngày.
  • Khác: Synthetics canary (kiểm tra endpoint định kỳ), RUM (trải nghiệm người dùng web), Contributor Insights (top-N IP/key gây tải).

Tối ưu

  • Lambda: tăng memory (CPU tăng theo), chọn arm64 (Graviton) để giá trên hiệu năng tốt hơn, dùng Power Tuning để tìm memory tối ưu, khởi tạo ngoài handler, giảm kích thước package, dùng SnapStart.
  • Concurrency: provisioned để hết cold start (có thể scale theo lịch bằng Application Auto Scaling), reserved để giới hạn hoặc giữ phần concurrency cho hàm quan trọng.
  • Database: RDS Proxy (pool kết nối), DAX, ElastiCache, read replica.
  • Messaging: SQS long polling, gửi và nhận theo batch (SendMessageBatch, tối đa 10), Kinesis enhanced fan-out khi có nhiều consumer.
  • Mạng và nội dung: CloudFront, API Gateway cache, nén response, S3 Transfer Acceleration.

Mẹo làm bài

  • 65 câu: phân bổ khoảng 2 phút mỗi câu. Đánh dấu câu khó (Flag) để quay lại. Không bỏ trống câu nào.
  • Từ khoá trong đề gợi ý đáp án:
  • "least operational overhead" thì chọn dịch vụ managed hoặc serverless.
  • "minimize impact" thì chọn canary.
  • "fastest rollback" thì chọn blue/green.
  • "without code changes" thì chọn cách cấu hình.
  • "most secure" thì chọn IAM role thay cho access key, và Secrets Manager.
  • Câu nhiều đáp án: loại đáp án sai trước, phải chọn đủ tất cả đáp án đúng.
